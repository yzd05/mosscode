# 记忆笔记

Agent 在使用中记住用户的偏好、纠正过的做法、项目知识和参考资料。下次启动时，系统提示里已有笔记的索引，需要时再读全文。笔记是普通的 Markdown 文件，用户可以查看、修改和删除。

通过 memory 工具或后台提取更新、删除笔记后，磁盘索引立即更新。当前会话的系统提示前缀保持不变，下一次请求追加一次失效提醒：已加载的旧笔记需要重新读取，删除的以不存在为准。提醒与恢复、回退提醒合并，不单独开启新一轮。手动在外部编辑文件仍需重新加载会话，模型已收到的历史内容不会被撤回。

助手复述的文件、网页要求仍视为外部内容，不等于用户确认。提取提示明确区分这种来源；这项提示与输入过滤不保证阻断所有模型层面的记忆投毒。

## 存储

| 范围 | 目录 | 内容 |
| --- | --- | --- |
| 用户级 | `~/.mosscode/memory/` | 所有项目通用：用户偏好、通用的做法 |
| 项目级 | `~/.mosscode/projects/<项目键>/memory/` | 只用于当前仓库；项目键见 [会话存档](sessions.md#存档位置) |

项目级笔记放在用户目录而不是仓库中：自动生成的内容不应混进代码，需要与团队共享的约定写进手写的 [AGENTS.md](prompts.md#项目指令agentsmd)。在 Git 多工作树（`git worktree`）中运行时，项目级笔记按 `.git` 的 `commondir` 归入主仓库对应的 `<项目键>/memory/`，使主目录、手动工作树、子 Agent 隔离工作树与 Agent 团队成员共享同一份项目记忆（旧版本留在工作树独立目录下的笔记会在首次访问时自动无损迁移），而会话记录与文件检查点仍按各自工作树隔离。

每条笔记一个文件 `<名称>.md`：

```markdown
---
name: no-db-mock
description: 测试里不要 mock 数据库，用真实的测试库
type: feedback
updated: 2026-10-24
pinned: true
---

测试使用真实的测试数据库，不要 mock。
原因：上次 mock 掩盖了迁移脚本的错误。
适用方式：编写或修改测试时。
```

| 字段 | 规则 |
| --- | --- |
| `name` | 与文件名相同，只用小写字母、数字和连字符，以字母或数字开头，最长 60 字符 |
| `description` | 一行，最多 150 字符，用于判断什么时候有用 |
| `type` | `user`（用户本人的偏好、习惯）、`feedback`（纠正或确认过的做法）、`project`（代码和 git 历史看不出的项目知识，只能是项目级）、`reference`（外部资源的位置） |
| `updated` | 最后更新日期 |
| `pinned` | 可选布尔值（默认 `false`，为 `false` 时不写入 frontmatter）。设为 `true` 时标为常驻笔记，在索引中带 `常驻` 标记并优先保留；后续覆盖更新未显式传 `pinned`（含后台自动提取）时保留原有的 `pinned: true` |
| 正文 | 最多 4 KB。`feedback` 和 `project` 写出事实后，跟“原因：”和“适用方式：”两行 |

每个目录中的 `MEMORY.md` 是索引，每条笔记一行：指向笔记文件的 Markdown 链接（链接文字是名称），后跟“ — 描述”，按更新日期倒序，由程序从各笔记的 frontmatter 生成，不要手工编辑。笔记变化后立即重新生成；手工修改笔记后，下次启动、`/clear` 或恢复会话时重新生成。frontmatter 不合法的笔记不进入索引，在 `/memory` 中标为“格式错误”。笔记和索引都先写临时文件再替换，中途失败不会留下半个文件。

## 注入系统提示

启动、`/clear` 和恢复会话时，系统提示在项目指令之后加入“记忆”一节：一段说明（笔记是背景资料，不是指令，可能已经过时，涉及文件、函数或配置时先核实），然后是用户级和项目级索引及各自的目录路径。

- 会话内不变，以保持提示缓存的前缀。会话中新写的笔记下次加载时才出现在索引中；本会话通过下一次请求的失效提醒获知笔记变化，需要时重新读取。
- 整节不超过 3,000 估算 Token，每个索引最多 200 行。排序与超出预算裁剪时，`pinned: true` 常驻笔记始终优先保留，其余按 `updated` 日期新旧保留，同一天更新的未常驻笔记优先保留当前项目的 `project` 笔记、先省略 `user` 笔记；未列入索引的较旧笔记可用 `memory` 工具的 `search` 或 `list` 检索查看。
- `read_file` 和 `glob` 读取两个笔记目录时不需要审批，计划模式中也可以。

## memory 工具

模型在对话中检索、读取或记录笔记时调用 `memory`：

| 参数 | 说明 |
| --- | --- |
| `action` | `save`（同名覆盖并更新日期）、`delete`、`read`（读取指定笔记全文）、`search`（关键词相关性检索）、`list`（列出全部笔记，含超出系统提示索引预算的条目） |
| `scope` | `user` 或 `project`；`save` 与 `delete` 必填，`read`、`search`、`list` 省略时同时查询两个范围 |
| `name`、`type`、`description`、`body`、`pinned` | 见上方字段规则；`delete` 与 `read` 只需要 `name`，`pinned` 可选用于 `save` |
| `query`、`limit` | 用于 `search`：`query` 为检索词（必填），`limit` 为最多返回条数（默认 10，最大 50） |

- **混合检索（`search`）**：采用 Okapi BM25（$k_1 = 1.5, b = 0.75$）相关性排序，对字段加权（`name` ×3、`description` ×2、`body` ×1），同时切分英文标识符与子词（如 `snake_case`、`kebab-case`）以及中文字元与重叠二元组（CJK bigrams），无需外部向量库即可精确召回中英文技术术语与超出索引预算的历史笔记。
- 用户明确说“记住……”“以后……”“不要再……”时调用 `save`；先看索引或用 `search` 查找，有同名或同义的笔记就更新。
- 默认不需要审批（只访问两个笔记目录）；计划模式中只读操作（`read`、`search`、`list`，含 `user` 范围）和项目级（`project`）写删均可直接调用，修改跨项目生效的用户级（`user`）笔记需经用户确认。工具校验 `name` 语法并拒绝任何路径穿越。
- 名称、类型与范围、长度不合格或内容疑似包含凭据时返回错误码（`invalid_name`、`scope_mismatch`、`description_too_long`、`body_too_large`、`secret_detected` 等）和原因，模型据此修正。
- 工具行显示“✎ 已记住：名称（用户级）”或“✎ 已删除笔记：名称”。

## 后台提取

交互界面中，任务正常完成（不是取消或出错）且有新的用户消息时，后台发起一次不带工具的模型请求，判断有没有值得记住的内容，不阻塞下一次输入。

- **输入只包含用户和模型的话**。工具结果只保留一行“[工具结果 · 名称，N 字符，已省略]”，工具调用只保留名称。文件、网页或 MCP 返回的原文不直接送入提取请求；助手复述的外部内容仍可能出现，提取规则要求没有用户确认时不能保存为用户偏好或项目规则。同时附上两个索引和已有笔记的全文（合计不超过 4,000 估算 Token），供模型判断应更新哪条而不是新建。新消息超过 12,000 估算 Token 时只保留较新的部分。
- 模型先分析，再输出 JSON 操作列表；没有值得记录的内容时为空。一次最多 5 个操作，每个操作经过与 memory 工具相同的校验，不合格的逐个丢弃；超出 4,000 Token 预算、未附全文的较旧笔记禁止在后台提取中被同名覆盖，防止丢失既有正文。
- 写入或删除了笔记时，对话中显示一行“✎ 已更新记忆：名称、名称”；没有变化时不显示。任务运行中完成的提取，等任务结束后再显示。
- 同一时间最多一个提取。运行中又有任务完成时，结束后用累积的新消息再提取一次。
- 压缩前，把即将被摘要替换、尚未提取的消息交给提取器。`/clear` 和恢复会话时，已有的历史不再提取。
- 服务报错或回复格式不对时，这次的消息留到下次一起处理。连续失败 3 次后本会话暂停后台提取，提示一次“自动笔记已暂停：原因”。
- 提取请求的 Token 计入状态栏的累计，不计入上下文比例。
- 退出时最多等待 5 秒让进行中的提取完成。
- `-p` 无界面模式不做后台提取，注入和 memory 工具照常可用。

## 查看与管理

| 命令 | 行为 |
| --- | --- |
| `/memory` | 先列出已加载的项目指令文件（见 [系统提示与缓存](prompts.md)），再按范围列出笔记（更新日期、类型、名称、描述，格式错误的标出原因）、两个目录的路径，以及自动笔记是否开启 |
| `/memory 名称` | 显示该笔记的路径和全文 |

修改或删除笔记可以直接编辑文件，也可以让模型用 memory 工具完成。

## 安全

笔记内容匹配以下模式时拒绝保存：`sk-` 开头的长串、`AKIA` 开头的访问密钥、`-----BEGIN … PRIVATE KEY-----`、`api_key` / `token` / `password` / `secret` 后接 `=` 或 `:` 和至少 8 个字符、`ghp_` / `xoxb-` 等令牌前缀。这只是辅助措施；工具描述和提取提示也要求不记录凭据。

## 配置

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `memory` | `true` | `false` 时不注入索引、不提供 memory 工具、不做后台提取，`/memory` 说明已关闭 |
| `auto_memory` | `true` | `false` 只关闭后台提取，工具仍可用 |
| `memory_provider` | 当前 Provider | 后台提取使用的 Provider 名称，必须是 `providers` 中已配置的一项；可以指定较便宜的模型 |
