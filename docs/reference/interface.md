# 终端界面

TUI 的布局、输入、命令、状态栏与配色。命令列表见 [README](../../README.md#使用)。

## 按键与流式显示

Enter 发送；Shift+Enter 或 Ctrl+J 换行；Esc 或 Ctrl+C 取消生成（有排队消息时第一次 Esc 只取回排队消息）；Ctrl+Q 退出。生成期间可以继续输入，Enter 将消息排队（见下文“输入与排队”）。服务返回 thinking 时展示过程并实时计时；开始输出正文后收起思考内容，只保留思考用时。正文逐块显示纯文本，完整收到后一次渲染 Markdown。服务未提供 thinking 时不显示或虚构思考过程。

## 布局与滚动历史

界面采用 Textual，自定义为简洁的终端对话布局：用户提供的机器人图标以浅绿色单色字符呈现，左侧小图标配右侧版本、配置的 `name` 和工作目录三行信息；名称仅在启动区显示一次，不展示 API `model` 字段；下方为聊天记录、上下横线输入区和模式状态行。正文、目录、工具输出和耗时使用终端正常前景色，不用淡灰或 dim 弱化；工具与少量语义标记按下文配色突出。移除了 Header、Footer、左上角默认图标及命令面板，不显示截图、Maximize、Keys 或可点击的退出入口。原始 SVG 参考保存在 `docs/ui/assets/robot-source.svg`。

默认以内联模式显示在原命令行下方，沿用终端背景并保留启动前的内容。稳定的启动信息、用户消息、完成回复、工具结果和本地命令结果按顺序写入终端原生滚动历史；实时界面仅保留正在生成的回复、未完成工具、输入框和命令菜单。鼠标报告关闭，滚轮由终端处理，因此同一终端多次启动后可翻阅此前留下的记录，当前会话很短也不会吞掉滚轮。鼠标拖选使用终端原生选择；应用不再提供 PageUp / PageDown 或 Ctrl+Home / Ctrl+End 的历史跳转。完成内容写入后通常不再由应用重绘，保留范围由终端滚动历史容量决定。**窗口宽度变化**是例外：终端会按新宽度重新折行已有的行，实时界面依赖的行数因此失效，旧行也保留旧宽度的折行。宽度稳定约 0.2 秒后，应用清空屏幕和终端滚动历史，再按新宽度重新输出本次会话的全部记录和实时界面（与 Pi 相同）。代价是启动前的命令行内容和更早的终端输出也会被清除；只改变高度不会触发重绘。长段中文按字符折行，不会在行尾被截断成“…”。模型的完整多轮消息仍保存在当前会话内存中，这不是持久化或会话恢复；旧版本未写入终端的隐藏内容无法事后补回。

消息排版参照用户提供的 Claude Code 截图：`❯` 与用户问题同行，`●` 与回复同行，不再额外显示 You / MossCode 角色标题。每轮完成后保留耗时。已完成内容写入终端原生记录，滚轮和跟随行为由终端控制。模型会话只在内存中保留，不提供退出后的恢复功能。终端可见行数与模型的 token 上下文容量无关：下一次请求包含全部已完成的消息，接近上下文窗口时较早的消息才会被压缩成摘要（见 [上下文管理](context.md)）。

应用使用终端默认背景，不铺独立底色，唯一的例外是用户消息：与 Claude Code 一样，`❯` 和用户输入铺一条灰色底色条（底色 `#4a4a4a`、文字 `#f2f2f2`，定义在 `appearance.py`），黑底和白底终端上都能与回复区分，实时界面和写入滚动历史的内容一致。其余内容使用正常对比度的“清晰文字”配色：前景色随终端设置生效，黑底通常显示亮字、白底通常显示深字。字体和字号仍由终端设置决定。原 `/theme` 只有一个选项，已移除。

## 本地命令的细节

命令和本地结果会显示在界面记录中。`/help`、`/clear`、`/model`、`/permissions`、单独的 `/plan` 不请求模型，也不进入模型上下文；`/compact` 用一次不带工具的请求把较早的对话压缩成摘要，压缩期间按 Esc 取消，历史不变（见 [上下文管理](context.md#何时压缩)）；`/plan 任务` 将任务发送给模型。未知命令（包括已移除的 `/theme`、`/do`）给出本地提示。权限档位和计划模式仅在本次会话内生效。

`/clear` 与 Claude Code 相同，清空屏幕和终端滚动历史（启动前的命令行内容也会清除），重新显示启动区，模型上下文和 Token 统计归零；若当前处于计划模式，下一次请求会重新告知模型计划模式的规则。`/model` 切换后保留完整对话历史；thinking 签名、Responses 推理等只对原模型有效的协议数据会被去掉，工具调用与结果以通用形式重建，因此可以在 Anthropic、OpenAI Responses 和 Chat 兼容协议之间来回切换。新客户端创建成功后才关闭旧客户端；凭据缺失等错误只显示提示，仍使用原模型。运行中不接受命令。

## 状态栏

首项为权限档位标记——`默认权限`、`⏵⏵ 接受编辑`（绿色）、`⏸ 计划模式`（琥珀色）、`⏵⏵ 跳过审批`（红色）；空闲且窗口宽度不小于 80 列时附加“(Shift+Tab 切换)”。随后是当前模型名、运行阶段/轮次/耗时（运行时）、排队条数、“上下文 约 N%”（收到第一次用量后显示，达到自动压缩阈值的 80% 时为琥珀色，见 [上下文管理](context.md#界面与无界面输出)）和会话累计 Token 用量。压缩期间运行阶段显示为“压缩上下文中”和计时。本次任务总耗时保留在消息下方。

## 输入与排队

输入框支持多行：Shift+Enter、Ctrl+J（或部分终端的 Alt+Enter）换行；也可在行尾输入 `\` 再按 Enter，反斜杠会替换为换行。Windows 控制台开启 VT 输入后，Enter 的按下记录只剩一个 `\r`，不带按键码和修饰键，Textual 原来的输入线程因此把 Shift+Enter 当作 Enter 发送。`windows_inline.py` 改用自己的输入线程：Enter 的记录（conhost 中同一批到达的松开记录带有 Shift 状态）或读取时键盘上的 Shift 状态，任一显示按下 Shift 就算 Shift+Enter（Windows Terminal 1.24 的松开记录也不带修饰键，只能依靠键盘状态），再转成 kitty 键盘协议的 `\x1b[13;2u` 交给解析器。不支持 Shift+Enter 的终端可用 Ctrl+J 或行尾反斜杠。粘贴的多行内容原样保留，不会被逐行发送。输入框随内容增高，最多 8 行，超出后在框内滚动。光标在首行时 ↑ 浏览本次会话的输入历史，在末行时 ↓ 返回较新的记录，越过最新一条后恢复未发送的草稿。调出的历史保持原样时不显示命令提示，因此连续按 ↑ / ↓ 可以经过 `/help` 这类命令记录；修改后提示恢复。手动输入 `/` 打开命令提示时，↑ / ↓ 用于选择提示。

任务运行时输入框保持可用。Enter 将消息排入队列，输入框上方显示“↳ 排队：…”，状态栏显示“已排队 N 条”。当前一轮工具执行完、下一次请求模型之前，所有排队消息合并为一条用户消息（以空行分隔）加入上下文，对话记录中逐条显示，用于在任务中途纠正方向。若模型在排队消息加入之前已给出最终回复，排队内容会在任务结束后作为下一个任务自动发送。想撤回或修改排队消息时，在输入框为空或光标位于首行时按 ↑：所有排队消息按顺序以空行连接放回输入框（输入框已有草稿时接在其前面），队列清空，排队提示和“已排队 N 条”随之消失，正在运行的任务不受影响、继续执行；可以编辑后重新按 Enter 排队，或清空放弃。没有排队消息时 ↑ 仍浏览输入历史。有排队消息时按 Esc 效果相同：只取回排队消息，任务继续，状态栏提示“再按 Esc 取消任务”；没有排队消息时 Esc 才取消整个任务。Ctrl+C 始终立即取消任务。取消、失败或达到上限而停止时不会自动发送，排队内容放回输入框供编辑。运行中输入的 `/` 命令不排队，提示完成后再发送。

输入 `/` 时，输入框下方显示命令候选，左侧为命令，右侧为中文解释；继续输入按前缀筛选。选中项的命令与说明用蓝色加粗文字突出，背景仍沿用终端设置。↑ / ↓ 选择，Tab 补全，Esc 收起并保留输入；编辑输入后恢复提示，删除并重新输入相同的 `/` 也可再次打开。Enter 在命令不完整时先补全，再按 Enter 执行完整命令；直接输入完整命令也可立即执行。Tab 补全 `/permissions` 后列出四个档位，补全 `/model` 后列出已配置的提供商名称。多行输入不显示命令提示。候选列表按窗口高度限制行数，可用方向键滚动查看，输入焦点始终保留在输入框。

## 工具行、diff 与配色

`edit_file` 和覆盖已有文件的 `write_file` 成功后，工具行下方显示带行号的 diff：删除行以 `-` 标红、新增行以 `+` 标绿，不同修改块之间以 `⋯` 分隔，最多显示 20 行，其余注明省略行数；新建文件显示前 8 行内容。diff 只用于界面显示，不发送给模型。

界面沿用原生背景。读取/搜索工具名称和成功勾号用绿色；工具参数及 Markdown 行内代码用蓝色；写入、修改、Shell 名称和执行中阶段用琥珀色；真正的失败工具及“失败”标签用红色。状态同时用 `● / ✓ / ×` 表示，取消、计划拦截和未启动调用用琥珀色 `!` 及中文说明，避免只靠颜色区分。工具行下方保留正常前景的结果摘要与耗时，不给整段回复着色。最终答复逐块输出，结束后渲染 Markdown。`--prompt` 使用相同工具流程，以纯文本显示结果。设计与实际界面预览见 `docs/ui/color-proposal.md`。

## 预览与烟测脚本

Agent Loop 界面预览：`docs/ui/previews/agent-plan.png`、`agent-loop.png` 与 `agent-loop-narrow.png`。运行 `python scripts/preview_agent.py` 可用固定模拟模型和临时演示文件重新生成实际 Textual 单元格/SVG 预览；`preview_tools.py` 保留基础工具预览。均不读取 API 配置。PNG 可在装有 Pillow 的开发环境中用 `scripts/render_terminal_preview.py` 从 JSON 绘制，模拟终端背景，不是应用绘制背景。

模拟界面预览见 `docs/ui/previews/`。开发人员可运行 `python scripts/preview_tui.py` 从实际 Textual compositor 导出 SVG 和单元格数据；该脚本使用固定模拟模型，不读取 API 配置。这是开发验证入口，产品界面没有截图功能。

Windows 真实控制台验证：`.\.venv\Scripts\python.exe scripts/verify_inline_terminal.py`。脚本自动使用模拟模型检查对话、命令补全、模型面板、退出和终端模式恢复；需在交互式终端运行，不读取 API 配置。

窗口宽度变化验证：`.\.venv\Scripts\python.exe scripts/verify_resize.py`。脚本在新的 conhost 窗口中用模拟模型回答一个问题，通过控制台 API 把窗口依次变窄再变宽，读回屏幕内容，检查问题、回答段落和状态栏各只出现一次且中文段落完整，窗口会自动关闭。加 `--no-redraw` 可在关闭重绘的情况下运行同一流程，用于对照问题现象。

按键验证：`.\.venv\Scripts\python.exe scripts/verify_keys.py`。pilot 测试直接把按键交给应用，绕过 Windows 控制台输入和驱动；该脚本在新的 conhost 窗口中用 `WriteConsoleInputW` 写入按键记录，经过控制台的 VT 转换和驱动，检查 Shift+Enter、Ctrl+J、行尾 `\` 换行、Enter 发送、含命令的历史浏览和 `/clear` 清屏。加 `--textual-input` 改用 Textual 原来的输入线程作对照。注入时 Enter 的松开记录与按下记录在同一批，脚本覆盖的是这条路径；真实键盘按键时查询 Shift 状态的路径需要手动确认。其他终端的按键记录可用 `scripts/dump_keys.py` 查看：它以与应用相同的控制台模式打印每条记录、读取时的 Shift 状态和交给解析器的文本，按 q 结束。

审批界面的真实 Textual 预览可用 `python scripts/preview_permissions.py` 生成到 `docs/ui/previews/permission-approval.svg`；脚本使用假模型与临时文件。Windows 控制台烟测同时验证键盘审批与终端模式恢复。
