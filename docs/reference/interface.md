# 终端界面

TUI 的布局、输入、命令、状态栏与配色。命令列表见 [README](../../README.md#使用)。

## 按键与流式显示

Enter 发送；Shift+Enter 或 Ctrl+J 换行；Esc 或 Ctrl+C 取消生成（有排队消息时第一次 Esc 只取回排队消息）；空闲且输入框为空时 0.5 秒内连按两次 Esc 打开 `/rewind`（见 [检查点与回退](sessions.md#检查点与回退)），面板、命令提示和排队消息仍先由 Esc 处理；Ctrl+B 把正在前台运行的子 Agent 转入后台（见 [子 Agent](subagents.md#前台与后台)）；有团队成员时 Ctrl+T 展开成员面板，选中成员按 Enter 查看它的对话（见 [Agent 团队](teams.md#成员面板与成员视图)）；Ctrl+Q 退出，有后台任务在运行时先确认。生成期间可以继续输入，Enter 将消息排队（见下文“输入与排队”）。服务返回 thinking 时展示过程并实时计时；开始输出正文后收起思考内容，只保留思考用时。正文逐块显示纯文本，完整收到后一次渲染 Markdown。服务未提供 thinking 时不显示或虚构思考过程。

## 布局与滚动历史

界面采用 Textual，自定义为简洁的终端对话布局：启动区左侧是吉祥物小幽灵（用半块字符拼成的彩色像素画，每两行像素占一行字符），右侧是版本、配置的 `name` 和工作目录三行信息；名称仅在启动区显示一次，不展示 API `model` 字段；下方为聊天记录、上下横线输入区和模式状态行。正文、目录、工具输出和耗时使用终端正常前景色，不用淡灰或 dim 弱化；工具与少量语义标记按下文配色突出。移除了 Header、Footer、左上角默认图标及命令面板，不显示截图、Maximize、Keys 或可点击的退出入口。

默认以内联模式显示在原命令行下方，沿用终端背景并保留启动前的内容。稳定的启动信息、用户消息、完成回复、工具结果和本地命令结果按顺序写入终端原生滚动历史；实时界面仅保留正在生成的回复、未完成工具、输入框和命令菜单。鼠标报告关闭，滚轮由终端处理，因此同一终端多次启动后可翻阅此前留下的记录，当前会话很短也不会吞掉滚轮。鼠标拖选使用终端原生选择；应用不再提供 PageUp / PageDown 或 Ctrl+Home / Ctrl+End 的历史跳转。完成内容写入后通常不再由应用重绘，保留范围由终端滚动历史容量决定。**窗口宽度变化**是例外：终端会按新宽度重新折行已有的行，实时界面依赖的行数因此失效，旧行也保留旧宽度的折行。宽度稳定约 0.2 秒后，应用清空屏幕和终端滚动历史，再按新宽度重新输出本次会话的全部记录和实时界面（与 Pi 相同）。代价是启动前的命令行内容和更早的终端输出也会被清除；只改变高度不会触发重绘。长段中文按字符折行，不会在行尾被截断成“…”。模型的完整多轮消息保存在会话内存中，并实时追加到会话存档（见 [会话存档与恢复](sessions.md)）；终端滚动历史本身不会被保存，旧版本未写入终端的隐藏内容无法事后补回。

消息排版参照用户提供的 Claude Code 截图：`❯` 与用户问题同行，`●` 与回复同行，不再额外显示 You / MossCode 角色标题。每轮完成后保留耗时。已完成内容写入终端原生记录，滚轮和跟随行为由终端控制。退出后可以用 `--continue`、`--resume` 或 `/resume` 恢复之前的会话，恢复时界面显示最近 20 条消息的简要形式（见 [会话存档与恢复](sessions.md#恢复)）。终端可见行数与模型的 token 上下文容量无关：下一次请求包含全部已完成的消息，接近上下文窗口时较早的消息才会被压缩成摘要（见 [上下文管理](context.md)）。

应用使用终端默认背景，不铺独立底色，唯一的例外是用户消息：与 Claude Code 一样，`❯` 和用户输入铺一条灰色底色条（底色 `#4a4a4a`、文字 `#f2f2f2`，定义在 `appearance.py`），黑底和白底终端上都能与回复区分，实时界面和写入滚动历史的内容一致。其余内容使用正常对比度的“清晰文字”配色：前景色随终端设置生效，黑底通常显示亮字、白底通常显示深字。字体和字号仍由终端设置决定。原 `/theme` 只有一个选项，已移除。

## 本地命令的细节

命令列表、解析规则、补全和提示词命令见 [命令](commands.md)。命令和本地结果会显示在界面记录中。本地命令（除 `/review` 外的全部内置命令）不请求模型，也不进入模型上下文；`/compact` 用一次不带工具的请求把较早的对话压缩成摘要，压缩期间按 Esc 取消，历史不变（见 [上下文管理](context.md#何时压缩)）；`/plan 任务`、`/do 任务` 将任务发送给模型；`/review` 回显命令原文，发给模型的是展开后的模板。未知命令（包括已移除的 `/theme`）给出本地提示，相近时提示正确的名称。权限档位和计划模式仅在本次会话内生效。

`/clear` 与 Claude Code 相同，清空屏幕和终端滚动历史（启动前的命令行内容也会清除），重新显示启动区，模型上下文和 Token 统计归零；若当前处于计划模式，下一次请求会重新告知模型计划模式的规则。`/model` 切换后保留完整对话历史；thinking 签名、Responses 推理等只对原模型有效的协议数据会被去掉，工具调用与结果以通用形式重建，因此可以在 Anthropic、OpenAI Responses 和 Chat 兼容协议之间来回切换。新客户端创建成功后才关闭旧客户端；凭据缺失等错误只显示提示，仍使用原模型。运行中只接受 `/tasks` 和 `/status` 两个命令。

## 状态栏

首项为权限档位标记——`默认权限`、`⏵⏵ 接受编辑`（绿色）、`⏸ 计划模式`（琥珀色）、`⏵⏵ 跳过审批`（红色）；空闲且窗口宽度不小于 80 列时附加“(Shift+Tab 切换)”。模型名显示在启动区，状态栏不重复；只有 `/model` 切换后启动区已经过时，才在这里显示新模型。随后是运行阶段/轮次/耗时（运行时）、排队条数、运行中的后台任务数（有前台子 Agent 时提示“Ctrl+B 转入后台”）、“上下文 约 9K / 1M（1%）”（收到第一次用量后显示，依次为估算的上下文大小、上下文窗口和占有效窗口的比例，达到自动压缩阈值的 80% 时为琥珀色，见 [上下文管理](context.md#界面与无界面输出)）和“缓存命中 N%”（会话累计的缓存读取 ÷ 总输入；服务没有报告缓存读取的请求出现后不显示）。Token 数和费用用 `/status` 查看。压缩期间运行阶段显示为“压缩上下文中”和计时。本次任务总耗时保留在消息下方。

## 输入与排队

输入框支持多行：Shift+Enter、Ctrl+J（或部分终端的 Alt+Enter）换行；也可在行尾输入 `\` 再按 Enter，反斜杠会替换为换行。Windows 控制台开启 VT 输入后，Enter 的按下记录只剩一个 `\r`，不带按键码和修饰键，Textual 原来的输入线程因此把 Shift+Enter 当作 Enter 发送。`windows_inline.py` 改用自己的输入线程：Enter 的记录（conhost 中同一批到达的松开记录带有 Shift 状态）或读取时键盘上的 Shift 状态，任一显示按下 Shift 就算 Shift+Enter（Windows Terminal 1.24 的松开记录也不带修饰键，只能依靠键盘状态），再转成 kitty 键盘协议的 `\x1b[13;2u` 交给解析器。不支持 Shift+Enter 的终端可用 Ctrl+J 或行尾反斜杠。粘贴的多行内容原样保留，不会被逐行发送。输入框随内容增高，最多 8 行，超出后在框内滚动。光标在首行时 ↑ 浏览本次会话的输入历史，在末行时 ↓ 返回较新的记录，越过最新一条后恢复未发送的草稿。调出的历史保持原样时不显示命令提示，因此连续按 ↑ / ↓ 可以经过 `/help` 这类命令记录；修改后提示恢复。手动输入 `/` 打开命令提示时，↑ / ↓ 用于选择提示。

任务运行时输入框保持可用。Enter 将消息排入队列，输入框上方显示“↳ 排队：…”，状态栏显示“已排队 N 条”。当前一轮工具执行完、下一次请求模型之前，所有排队消息合并为一条用户消息（以空行分隔）加入上下文，对话记录中逐条显示，用于在任务中途纠正方向。若模型在排队消息加入之前已给出最终回复，排队内容会在任务结束后作为下一个任务自动发送。想撤回或修改排队消息时，在输入框为空或光标位于首行时按 ↑：所有排队消息按顺序以空行连接放回输入框（输入框已有草稿时接在其前面），队列清空，排队提示和“已排队 N 条”随之消失，正在运行的任务不受影响、继续执行；可以编辑后重新按 Enter 排队，或清空放弃。没有排队消息时 ↑ 仍浏览输入历史。有排队消息时按 Esc 效果相同：只取回排队消息，任务继续，状态栏提示“再按 Esc 取消任务”；没有排队消息时 Esc 才取消整个任务。Ctrl+C 始终立即取消任务。取消、失败或达到上限而停止时不会自动发送，排队内容放回输入框供编辑。运行中输入的 `/` 命令不排队：`/tasks`、`/status` 立即执行，结果显示在当前位置；其他命令提示完成后再发送。

输入 `/` 时，输入框下方显示命令候选，左侧为命令，右侧为中文解释；继续输入按前缀筛选。选中项的命令与说明用蓝色加粗文字突出，背景仍沿用终端设置。↑ / ↓ 选择，Tab 补全，Esc 收起并保留输入；编辑输入后恢复提示，删除并重新输入相同的 `/` 也可再次打开。Enter 在命令不完整时先补全，再按 Enter 执行完整命令；直接输入完整命令也可立即执行。Tab 补全 `/permissions` 后列出四个档位，补全 `/model` 后列出已配置的提供商名称。多行输入不显示命令提示。候选列表按窗口高度限制行数，可用方向键滚动查看，输入焦点始终保留在输入框。

## 引用文件

在行首或空白之后输入 `@`，输入框下方列出项目中的文件和目录，继续输入按模糊匹配筛选（例如 `@tui` 找到 `src/mosscode/tui.py`），最多 12 项。列表遵守 `.gitignore`，跳过 `.git`、`.venv`、`node_modules` 等目录；有 `rg` 时用 `rg --files` 列出，否则用内置遍历，在后台读取并缓存 10 秒，大项目第一次输入 `@` 时稍后才出现候选。只输入 `@` 时列出项目根目录的内容。↑ / ↓ 选择，Tab 或 Enter 把光标前的词换成 `@路径`，文件后面加一个空格，目录以 `/` 结尾并接着列出其中的内容；路径含空格时加引号（`@"my notes.md"`）。在消息中间补全时，光标停在补全的路径后面，后面的文字不变。`a@b` 这样 `@` 前面不是空白的文字不触发；Esc 收起菜单。

发送时，每个指向已有文件或目录的 `@路径` 都会被读取，文件内容附在消息后面一起发给模型：
- 路径相对项目根目录，也可以写绝对路径或 `~` 开头的路径。路径末尾的英文标点不算路径；全角标点会结束路径，所以 `看下 @a.py，再改` 可以直接写。
- `@文件#L10-20` 只附第 10 到 20 行，`@文件#L10` 从第 10 行开始。
- 文件内容与 `read_file` 的结果相同（行号、长文件只附第一页并提示下一页的 offset、图片文件附上图片），并记为模型已读，模型可以直接编辑。目录附上一层列表，最多 100 项。
- 一条消息最多附上 10 个引用；附上的内容超过 112 KiB 后，后面的文件只给出路径，由模型自己读取。
- 读取不经过审批，项目外的路径也一样，因为路径是你自己输入的；显式拒绝规则（见 [权限](permissions.md)）仍然生效，被拒绝的文件只附上原因。不指向已有路径的 `@词` 原样发送。

已发送的消息下方用暗色列出附上了什么，例如“└ 已附上 src/a.py（120 行）、docs/（目录，8 项）”；恢复的会话也会列出。消息本身保持原样：回退（`/rewind`）、找回历史消息和记忆提取看到的都是你输入的文字，回退到这条消息之前时附上的内容一起去掉。运行中排队的消息不展开 `@`。`-p` 同样展开引用（见 [Provider](providers.md#无界面模式与输出格式)）。

## 图片

按 Alt+V 附加剪贴板中的图片：截图（Windows 的 Win+Shift+S、macOS 的 Cmd+Ctrl+Shift+4）或在资源管理器、访达中复制的图片文件都可以。Windows Terminal 自己处理 Ctrl+V，只能粘贴文字，所以 Windows 上用 Alt+V；在 Ctrl+V 能传给程序的终端（多数 macOS 和 Linux 终端）中，Ctrl+V 先查找图片，剪贴板里没有图片时照常粘贴文字。Linux 读取剪贴板需要 `wl-paste`（Wayland）或 `xclip`（X11）。剪贴板在后台线程中读取，最多等 5 秒，超时或出错时状态栏说明原因，界面不会卡住。

把图片文件拖进终端，或粘贴只由已有图片路径组成的文字（可带引号，多个路径以空格分隔，也接受 `file://` 地址和 macOS 的 `\ ` 转义空格）时，路径换成图片；粘贴内容只要有一项不是图片文件，就按原文插入。手动输入的路径不会转换，模型可以用 `read_file` 自行读取。相对路径按工作目录解析。

每张图片在光标处插入占位符 `[图片 #N]`，输入框上方列出本条消息的图片：编号、来源（“剪贴板”或文件名）、原始尺寸和文件大小，缩放后发送的图片另注发送尺寸。编号在本次运行中递增，发送后不会重新开始。发送时只带上文字中仍然存在的占位符对应的图片，每张图片紧跟在它的占位符之后；删掉占位符就取消了这张图片。图片在发送时才写入会话目录的 `images/`（见 [会话存档与恢复](sessions.md)），处理方式与 `read_file` 相同（见 [工具](tools.md#图片)）。运行中排队的消息同样带上图片；用 ↑ 调出的历史消息在同一次运行中仍带着原来的图片。

已发送的用户消息下方用暗色列出它的图片；恢复的会话也会列出（编号、尺寸和大小）。当前模型不接受图片（`providers.<名称>.images: false`，见 [Provider](providers.md#图片输入)）时，Alt+V 和拖入图片都只提示“当前模型不支持图片”，不读取剪贴板；拖入的路径保留为文字，Ctrl+V 照常粘贴。`/status` 的“图片”一行显示当前模型能否接收图片。粘贴图片只把它附加到消息中，不经过权限审批。

## 工具行、diff 与配色

`edit_file` 和覆盖已有文件的 `write_file` 成功后，工具行下方显示带行号的 diff：删除行以 `-` 标红、新增行以 `+` 标绿，不同修改块之间以 `⋯` 分隔，最多显示 20 行，其余注明省略行数；新建文件显示前 8 行内容。diff 只用于界面显示，不发送给模型。

界面沿用原生背景。读取/搜索工具名称和成功勾号用绿色；工具参数及 Markdown 行内代码用蓝色；写入、修改、Shell 名称和执行中阶段用琥珀色；真正的失败工具及“失败”标签用红色。状态同时用 `● / ✓ / ×` 表示，取消、计划拦截和未启动调用用琥珀色 `!` 及中文说明，避免只靠颜色区分。工具行下方保留正常前景的结果摘要与耗时，不给整段回复着色。最终答复逐块输出，结束后渲染 Markdown。`--prompt` 使用相同工具流程，以纯文本显示结果。
