# 命令

以 `/` 开头的输入不经过模型，直接执行本地操作，或者把一段规程作为一条消息发给模型。内置命令登记在 `src/mosscode/builtin_commands.py` 的 `BUILTIN` 注册表中；启动时再为每个 Skill 加一条命令（见 [Skill](skills.md)）。解析、补全菜单、`/help` 和无界面模式都读这一份登记。

除内置命令外，每个 Skill 是一条 `/<名称> [参数]` 命令，例如内置 Skill `/commit`、`/init`、`/review`、`/test`（见 [Skill](skills.md#内置-skill)）。补全菜单和 `/help` 中，Skill 命令的描述后面带 `[skill]`；`user-invocable: false` 的 Skill 不列出，但输入全名仍可执行。已连接的 MCP Server 声明提示词时，还会自动注册 `/mcp__<server>__<prompt>` 命令（描述后带 `[mcp:<server>]`），支持 `key=value` 与位置参数并在消息发送前支持 `@server:uri` 引用 MCP 资源（见 [MCP 资源与提示词](mcp.md#资源与提示词)）。

本地命令不请求模型，结果只显示在界面中，不进入模型上下文；`/compact` 例外，它用一次不带工具的请求生成摘要。任务运行期间只接受 `/tasks`、`/loop`、`/todo`、`/goal`（查看或清除）、`/status`、`/worktree`、`/worktree list`、`/team`（`delete` 除外）和 `/swarm`（不带参数或 `status`）（查看或停止任务、管理定时巡检、查看状态，不改变正在运行的任务所依赖的状态）；输入其他命令会提示“运行中只能排队消息和使用 /tasks、/todo、/goal、/status、/worktree list，其他命令请在完成后发送”，输入保留在框中。

## 目标

`/goal <条件>` 给会话设定一个完成条件（最多 4,000 字），例如 `/goal tests/test_parser.py 全部通过，ruff check 没有错误`。条件立即作为一条消息发给模型；之后每轮结束时，MossCode 另发一次不带工具的请求判断条件是否已经满足，未满足时自动开始下一轮，直到达成、判断为无法达成或暂停。

- **判断**：判断请求只看条件和对话的最近部分（最近的回复全文、最近 20 个工具结果各截取 1,000 字，合计约 16k Token），只认对话中出现的证据，模型自己声称完成不算。结论是“已达成”“尚未达成”或“无法达成”：已达成和无法达成都会清除目标并在对话中显示理由；尚未达成时显示“◎ 目标尚未达成：理由，继续下一轮”，理由也会告诉模型。判断默认用当前模型，`config.yaml` 中 `goal_provider` 可以指定较便宜的模型（没有设置时用 `memory_provider`）。判断的 Token 计入本会话用量。
- **续跑**：下一轮的消息是一条合成消息“继续推进目标……”，不显示为你的消息；目标进行中，条件、已用轮数和上一次判断的理由作为提醒追加在每轮的第一次请求中（写入历史，内容不变时不重复，见 [提醒](prompts.md#环境补充与模式提醒)）。目标不改变权限档位，需要审批的工具照常询问，`ask_user` 照常等待回答；想让它无人值守地运行，先用 Shift+Tab 或 `/permissions` 切换到合适的档位。
- **暂停**：以下情况自动续跑暂停，目标保留，对话中说明原因：本轮被取消（Esc，包括判断进行中按 Esc）、出错、达到最大迭代轮数、触发[重复调用检测](tools.md#重复调用检测)、回复被截断且自动续写 3 次后仍未写完（见 [重试与错误](providers.md#重试与错误)）；连续 3 轮没有调用工具；连续 3 次无法判断；自动运行的轮数达到上限（`goal_max_turns`，默认 30）。暂停后你发送任何消息，这一轮照常处理，结束后恢复自动续跑；也可以输入 `/goal` 直接继续。因轮数上限暂停的，继续后再给同样多的轮数。
- **等待后台任务**：一轮结束时还有子 Agent 或后台命令在运行，先不判断，等它们的通知触发的那一轮结束后再判断。
- **查看与清除**：`/goal` 显示条件、已运行时间、轮数、Token 用量和最近一次判断的理由；没有目标时显示最近一次结束的目标。`/goal clear`（`stop`、`off`）清除目标；`/clear` 也会清除。运行中可以使用 `/goal` 查看和 `/goal clear`，设置新目标要等本轮结束。
- **状态栏**：目标进行中显示“◎ 目标”和已运行时间，暂停时显示“◎ 目标已暂停”。
- **会话记录**：设置、清除、达成和无法达成都写入会话记录（见 [会话存档与恢复](sessions.md#记录格式)）。恢复的会话有未完成的目标时，目标以暂停状态恢复，计时和轮数从零开始，等你发送消息或输入 `/goal` 后继续。
- `-p` 不处理斜杠命令，没有目标模式。

## 定时巡检（/loop）

`/loop` 用于在当前交互会话中按固定周期重复执行同一条提示词或斜杠命令（例如轮询 CI 构建、关注 PR 新评论、定期运行 `/test` 或 `/review`）。

- **创建与管理语法**：
  - 前置间隔：`/loop 5m 检查 CI 是否通过`、`/loop 30s 查看构建日志`、`/loop 2h 巡检错误告警`（支持单位 `s`/`sec`/`secs`、`m`/`min`/`mins`、`h`/`hr`/`hrs`、`d`/`day`/`days` 以及中文 `秒`、`分`、`分钟`、`小时`、`天`）；
  - 尾部间隔：`/loop check PR comments every 5m`；
  - 省略间隔（默认 `5m`，即 5 分钟）：`/loop 检查部署进度`；
  - 定时调用斜杠命令或 Skill：`/loop 30m /test`、`/loop 10m /review`（禁止 `/loop /loop ...` 自递归嵌套）；
  - 自定义次数上限：可选 `--max-runs <N>`（或 `--count <N>`，范围 `1`–`1000`，默认 `100`），例如 `/loop --max-runs 10 1m 检查端口就绪`；
  - 查看列表：`/loop` 或 `/loop list` 显示本会话活跃与已结束的定时巡检（任务 ID、状态、`每 <间隔>`、`已运行 N/M 次`、下次触发倒计时或“等待空闲触发”、提示词首行）；
  - 停止巡检：`/loop stop <id>` 或 `/loop stop all`（支持别名 `cancel`）停止指定或全部运行中的定时巡检。
- **仅空闲触发与不补发（Idle-Only & No Catch-Up）**：计时器到期时，若会话正处于繁忙状态（正在生成回复、执行工具或命令、等待权限审批或 `ask_user` 回答，或 `/goal` 正在自动续跑），不会打断或抢占当前轮次，而是将任务标记为 `pending_fire`（单布尔位合并：即使繁忙期间跨越多个周期也绝不积压补发，空闲恢复后只触发**一次**）。多条定时巡检同时到期时通过内部互斥锁串行触发，前一轮完成后才从当前时刻重新计算下一轮延迟，避免慢速轮次引发零间隔连环空转。
- **非负防惊群抖动（Jitter）**：每次睡眠在设定间隔上附加 `[0, min(10% × 间隔, 30s)]` 的均匀非负随机抖动，既错开多条定时任务的触发峰值，又保证实际间隔绝不短于用户设定的最小间隔（如 `10s` 不会提前触发）。
- **安全上限与会话生命周期**：轮询间隔下限为 `10 秒`、上限为 `7 天`，提示词最长 `4,000` 字；单会话最多同时运行 `20` 个定时巡检（独立配额，不占用后台子 Agent 的 `agent_max_background` 槽位）；每条计划默认最多运行 `100` 次、最长有效期 `7 天`，达到任一上限后自动标记完成并记录结束原因。执行 `/clear`、`/resume` 切换会话或关闭会话时，所有运行中的定时巡检全部自动取消；`-p` 无界面模式单轮即退出，不支持 `/loop`。
- **界面、ACP 与 `/tasks` 联动**：TUI 状态栏在存在活跃计划时显示 `定时 K`，每次触发先打印 `⏰ 定时巡检 tN（第 k 次）：…`；普通提示词以合成消息（`synthetic="loop"`，附带 `[定时任务 tN · 每 … · 第 k 次]` 头标）提交，`/` 开头的提示词直接走斜杠命令分派器。ACP 编辑器会话同样暴露 `/loop`，空闲期到期的计划安全排队并在 `session/prompt` 轮次边界内执行，绝不发送非请求的 JSON-RPC 帧。所有计划同步纳入 `/tasks`（汇总行展示 `每 <间隔> · 已运行 N/M 次`，支持 `/tasks <id>` 查看详情与 `/tasks stop <id>`、`task_stop` 停止）。

## 输入如何解析

去掉前导空白后，第一个空白字符（空格、制表符或换行）之前的部分是命令词，之后的部分去掉首尾空白是参数，参数可以跨行。

| 输入 | 处理 |
| --- | --- |
| 只含空白 | 忽略 |
| 命令词匹配 `/[A-Za-z][A-Za-z0-9_-]*` 且已登记 | 执行命令。命令名不区分大小写（`/Help`、`/PERMISSION plan` 都可以），参数原样保留 |
| 命令词匹配但未登记 | 显示“未知命令 /xxx。输入 /help 查看命令；要把以 / 开头的文字发给模型，在开头再加一个 /。”有相近的名称（`difflib`，相似度 0.6 以上）时，前面加“是不是想输入 /yyy？” |
| 命令词不匹配，如 `/etc/hosts 怎么改`、`/tmp/a.py`、`/ 你好` | 整段原样作为普通消息发给模型 |
| 单独的 `/` | 打开补全菜单；按 Enter 提示“输入 /help 查看命令。” |
| 以 `//` 开头 | 去掉一个 `/` 后作为普通消息发送，例如 `//api 这个接口怎么设计` |

参数不符合命令要求时，例如 `/clear extra`，显示“/clear 不接受参数。用法：/clear”，不执行命令。

## 发给模型的命令

Skill 命令和提示词命令（`kind` 为 `prompt`，目前没有内置的此类命令）把一段文字（加上参数）发给模型：

- inline 方式的 Skill 和提示词命令把规程或模板作为一条普通的用户消息发出。工具、权限审批、计划模式、压缩和存档都和手动输入的消息相同。带参数时，提示词命令把参数以“补充要求：<参数>”附在模板后面；Skill 先替换正文中的 `$ARGUMENTS`，没有时同样追加。
- fork 方式的 Skill（如 `/review`）先显示“在独立上下文中运行 Skill <名称>”，由子 Agent 在新的历史中执行，主对话只增加命令原文和最终回复这一对消息（见 [两种执行方式](skills.md#两种执行方式)）。

规程只是提示：内置 `/review` 要求只读，但子 Agent 的写入和命令仍按当前档位审批。需要硬性保证时，先 `/plan` 进入计划模式再执行。

生成的用户消息记录了命令原文（消息的 `command` 字段，例如 `/review 安全`），并写入会话存档。界面回显、恢复会话后的重放、会话列表的标题，以及记忆提取看到的用户输入，都使用命令原文，不显示展开后的规程；模型收到的仍是完整规程。没有 `command` 字段的旧存档照常读取。

## 补全

- 输入以 `/` 开头的单行文字时，菜单按前缀列出命令，每行是用法和描述。前缀匹配到别名时，菜单显示主命令，描述后注明“（别名 /quit）”，选中后补全为主命令。
- Tab 补全高亮项；只有一项匹配时它默认高亮。按 Esc 收起菜单后，如果输入是某个命令唯一的前缀，Tab 仍然补全。
- 有参数候选的命令，Tab 补全命令名后追加空格，菜单换成参数候选：`/permissions` 的档位、`/model` 的提供商名与 `<当前提供商>/<模型>`、`/mcp` 的 Server 名（有连接时）、`/memory` 的笔记名、`/skills` 的 Skill 名和 `reload`、`/hooks` 的 Hook `id` 和 `reload`、`/loop` 的 `list`/`stop` 与常用间隔、`/worktree` 的子命令和 `remove <工作树名>`、`/team` 的团队与成员子命令、`/swarm` 的 `status`/`on`/`off`。

## 无界面模式

`-p` 的文字按同样的规则解析：

- 普通消息（包括 `/etc/hosts 是什么`，以及去掉一个 `/` 的 `//` 开头文字）照常发送。
- Skill 命令和提示词命令展开后执行，输出格式与普通 `-p` 相同。fork 方式的 Skill 先在 stderr 提示“在独立上下文中运行 Skill <名称>”，再由子 Agent 执行；Skill 指定的 `model` 不存在或所需工具不可用时不发请求，stderr 说明原因，以退出码 1 结束。
- 本地命令以退出码 2 结束，stderr 显示“/clear 只能在交互界面中使用。”
- 未知命令同样以退出码 2 结束，stderr 显示未知命令的提示。

## 添加命令

在 `BUILTIN` 中加一个 `Command`：

```python
Command("name", "一行描述", "/name [参数]", "local", aliases=("n",), argument="optional",
        argument_hint="[参数]", handler=_name, complete=_candidates)
```

- `kind` 为 `local` 时必须有 `handler`，签名为 `async (ctx: CommandContext, argument: str) -> None`。为 `prompt` 时必须有 `template`。`skill` 只由 Skill 扫描生成（`skill` 字段为 Skill 名），不要手写；新增可复用的提示词时写一个 Skill 更方便。
- `argument` 为 `none`、`optional` 或 `required`，分派前校验。
- `complete` 返回参数候选 `(值, 描述)` 的列表；返回空列表时 Tab 不追加空格。
- `hidden=True` 的命令不出现在菜单和 `/help` 中，但输入全名仍可执行。
- `while_running` 为 `True` 时任务运行期间也能执行；也可以是 `(argument) -> bool`，按参数决定，例如 `/worktree` 只允许 `list`。
- 名称和别名必须匹配 `[a-z][a-z0-9_-]*`，并且（转小写后）互不重复。违反时导入模块就抛出 `CommandConflict`，程序无法启动。

处理函数只通过 `ctx` 工作。读写状态（权限档位、会话、用量、MCP）用 `ctx.conversation`；改界面用 `ctx.ui`。`ctx.ui` 是 `CommandUI` 协议，由 `MossCodeApp` 实现：

| 方法 | 用途 |
| --- | --- |
| `note(text, style=None)` | 在对话中显示本地结果 |
| `submit(prompt, *, command=None, fork=None)` | 发起一次 Agent 请求；`command` 写入消息的 `command` 字段；`fork` 为 `ForkRequest` 时在子 Agent 中运行该 Skill |
| `refresh_status()` | 重算上下文比例并重绘状态栏，在改变档位、模型或会话后调用 |
| `clear_screen()` | 清空屏幕和终端滚动历史，重新显示启动区 |
| `choose(title, options, current, on_pick)` | 打开选择面板并立即返回；用户按 Enter 时以所选序号调用 `on_pick`，按 Esc 时什么都不调用 |
| `compact(instructions)` | 带进度行的手动压缩 |
| `resume(session_id)` | 带进度的恢复与重放 |
| `switch_model(name, model=None)` | 切换到指定提供商；给出 `model` 时复用该提供商连接并覆盖其模型 |
| `exit()` | 退出应用 |

`choose` 用回调而不是等待返回值：Textual 的消息处理函数中等待用户输入会让界面停止响应。测试用一个记录调用的假实现（见 `tests/test_commands.py` 的 `FakeUI`），不启动界面就能测试命令逻辑。
