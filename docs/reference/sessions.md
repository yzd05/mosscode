# 会话存档与恢复

每个会话的消息实时追加到一个 JSONL 文件。程序退出、崩溃或断电后，可以选择一个会话接着对话。

## 存档位置

```
~/.mosscode/projects/<项目键>/
  sessions/
    <会话 ID>.jsonl     对话记录
    <会话 ID>.lock      使用中的锁
    <会话 ID>/          会话目录：tool-results/、images/、checkpoints/、compact-<n>.md、hooks.log、subagents/
```

- **项目键**由启动目录的绝对路径生成：路径末尾的可读部分加上 8 位哈希，例如 Windows 上 `C:\Users\me\projects\app` 得到 `c--users-me-projects-app-1a2b3c4d`。同一目录总是得到同一个键。
- **会话 ID** 形如 `20261024-153000-a1b2`（启动时间加 4 位随机串）。
- 第一条消息写入时才创建文件；没有任何消息的运行不留下文件。
- 会话目录（存盘的大结果、压缩记录，见 [上下文管理](context.md#会话目录)）与 JSONL 同名。恢复后继续使用同一目录，历史中引用的路径仍然有效。
- 图片保存在会话目录的 `images/` 中，文件名是图片内容 SHA-256 的前 32 位十六进制加扩展名，相同图片只存一份。JSONL 中的图片只记录文件名、媒体类型、宽、高、字节数和替代文本，不含图片数据。子 Agent 和团队成员读到的图片保存在各自对话记录旁的同名目录中，例如 `subagents/<任务 id>/images/`。

## 记录格式

每行一条 JSON 记录：

| type | 内容 |
| --- | --- |
| `session` | 第一行：`id`、`cwd`、`created`、`mosscode`（版本） |
| `message` | 一条进入历史的消息，带写入时间 `time`。用户消息与第一次完整回复一起写；一批工具结果在执行结束后写一次；生成到一半的回复不写 |
| `compact` | 压缩成功：历史变为 `boundary`（摘要消息）加上当前历史的最后 `keep` 条；`record` 是压缩记录文件的路径 |
| `provider` | `/model` 切换：此前消息中只对原模型有效的数据（thinking 签名、加密推理）清除 |
| `checkpoint` | 文件检查点：`message`（当时最新的用户消息 id）、`path`（工作区内为相对路径）、`blob`（快照文件名，`null` 表示文件当时不存在），过大的文件带 `too_large: true` |
| `rewind` | `/rewind` 退回对话：历史变为前 `keep` 条，`message` 是退回的那条消息 |
| `task` | 子 Agent 任务的开始（`event: start`）和结束（`event: end`）：任务 id、类型、标签、状态、对话记录路径。恢复时跳过，不重新运行旧任务 |

子 Agent 的消息不进入主对话历史，写在会话目录的 `subagents/<任务 id>.jsonl` 中：第一行是 `{"type": "subagent", ...}` 任务信息，之后是与上表相同的 `message` 记录（见 [子 Agent](subagents.md#对话记录)）。后台任务的通知是 `synthetic` 为 `task-notification` 的用户消息，随主对话历史保存。消息中 `@` 引用的文件内容是紧跟在这条消息后面、`synthetic` 为 `file-mentions` 的用户消息（见 [终端界面](interface.md#引用文件)），同样随历史保存，恢复会话后仍在上下文中。在输入框中用 `!` 执行的命令及其输出是 `synthetic` 为 `shell-command` 的用户消息（见 [终端界面](interface.md#执行命令)），会话最后一条是它时也不会被当作“没有得到回复”的消息放回输入框。

每条记录用一次 `write()` 写入后立即 `flush()`。追加前如果文件末尾是半行，先截断到最后一个完整行。写入失败（磁盘满、权限错误等）时提示一次“会话存档写入失败：原因，本会话之后的消息不会被保存。”，对话继续。

会话在使用时持有 `<会话 ID>.lock` 上的操作系统独占锁，进程退出或崩溃时由系统释放。另一个 MossCode 正在使用的会话不能恢复，提示“该会话正在另一个 MossCode 中使用。”。

用户输入的消息带一个 12 位十六进制的 `id`，检查点和 `rewind` 记录用它指向消息；摘要边界、任务通知等程序生成的消息没有 `id`。旧版本会跳过它不认识的 `checkpoint` 和 `rewind` 记录。

`/clear` 结束当前会话：下一条消息开始新的会话 ID 和新的会话目录。

## 恢复

| 入口 | 行为 |
| --- | --- |
| `-c` / `--continue` | 恢复本项目最近活动的会话 |
| `--resume ID` | 恢复指定会话；可以与 `-p` 一起使用 |
| `--resume`（不带 ID） | 交互界面启动后打开会话列表；不能与 `-p` 一起使用 |
| `/resume` | 空闲时打开会话列表：最后活动时间、标题、消息数、ID 后 4 位，当前会话和使用中的会话有标注。↑ / ↓ 选择，Enter 恢复，Esc 收起 |
| `/resume ID` | 直接恢复指定会话 |

列表显示本项目最近 20 个会话，按文件修改时间倒序。标题是第一条用户消息的第一行（最多 40 字符），消息数按行计数，都直接从 JSONL 读取。指定的 ID 不存在时提示并列出最近的几个 ID。任务运行中不能恢复。

恢复时逐行重放记录，并修复中断留下的问题：

| 情况 | 处理 |
| --- | --- |
| 无法解析的行、缺字段的行 | 跳过，提示“跳过了 N 行无法读取的记录。” |
| 工具调用没有结果（执行中被中断） | 补上错误码为 `interrupted` 的结果“会话中断，这个调用可能未执行，也可能执行了但结果丢失……”，提示“N 个工具调用在中断时没有结果，已标记为“会话中断”；模型会先检查状态。” |
| 找不到对应调用的工具结果 | 删除 |
| 图片文件缺失 | 该图片改为文字 `[图片已丢失：替代文本]`，会话照常恢复，提示一次“N 张图片的文件已丢失，已改为文字说明。” |
| 末尾没有得到回复的用户消息 | 从历史中移除，文本放回输入框（`-p` 中输出到 stderr），提示“最后 N 条消息没有得到回复，已放回输入框，可以修改后重新发送。” |
| 存档的 Provider 名称或协议与当前不同 | 与 `/model` 切换相同，清除只对原模型有效的数据 |
| 估算超过自动压缩阈值 | 立即压缩一次再等待输入（`auto_compact: false` 时也执行，不计入熔断）；失败时会话仍然恢复，提示“恢复的会话超出上下文窗口，压缩失败：原因；可以 /compact 重试或 /clear” |
| 上次活动距现在 ≥ 6 小时 | 恢复后的第一次请求附加一次提醒：已过去约 N 小时，文件、分支和依赖可能已经变化，先重新读取再下结论。提醒不写入历史和存档 |

恢复后重置的状态：读过的文件记录（修改前必须重新读取）、“本会话允许”的授权、Token 累计、模式提醒。权限档位保持本进程当前的档位，计划模式不恢复。项目指令、git 快照和记忆索引重新加载。新消息继续追加到原来的 JSONL。

界面先显示“已恢复会话 · 标题 · N 条消息 · 上次活动 时间”，再显示最近 20 条消息的简要形式（用户消息原文、回复、每个工具调用一行，压缩边界显示为“（较早的对话已压缩）”），然后是上表中的提示。

## 检查点与回退

每条用户消息进入历史时开始一轮检查点。`write_file` 和 `edit_file` 在一轮中第一次写某个文件之前（检查通过之后、真正写入之前），保存它当时的字节；文件不存在时记为“不存在”。同一轮里再写同一个文件不再保存；权限拒绝、“需要先读取”、匹配失败等没有写入的调用不留记录。

- **跟踪范围**：主对话，以及在主工作区运行的子 Agent（前台和后台、Skill 的 fork）。它们改的文件记在当时最新的那条用户消息下面。
- **不跟踪**：`execute_command` 等命令改的文件、工作树中的子 Agent 和团队成员、MCP 工具和外部程序的改动。一个文件只要被编辑工具改过，恢复时就会写回快照，不管之后是谁改的。
- **存储**：快照按内容 SHA-256 的前 32 位十六进制命名，存在会话目录的 `checkpoints/` 中，相同内容只存一份；超过 10 MB 的文件不保存，记为“过大”。保存失败（磁盘满、权限）时写入照常进行，本会话第一次失败时提示一次。检查点随会话存档保留 30 天，一起清理。

`/rewind`（别名 `/checkpoint`）列出当前上下文中的用户消息，最新的在最上面；之后有文件改动的附上“之后改动 N 个文件”。压缩掉的消息和 `/clear` 之前的会话不列出。选中消息后选择操作：

| 操作 | 效果 |
| --- | --- |
| 恢复代码和对话 | 两者都退回到这条消息发出之前 |
| 只恢复对话 | 历史截断到这条消息之前，文件不变 |
| 只恢复代码 | 文件退回，对话保留；下一次请求附带一次性提醒，列出恢复的文件，要求模型重新读取后再修改 |
| 取消 | 不做任何事 |

这条消息之后没有文件改动时，只有“只恢复对话”和“取消”。

- **恢复代码**：对这条消息之后记录过的每个文件，取它之后的第一份快照写回；当时不存在的文件被删除。结果列出恢复、删除、跳过（过大、快照丢失）和失败的文件，一个文件失败不影响其他文件。只回退过对话、文件还保留着的那几轮，它们的快照也算在内，所以之后再退回到更早的消息时，这些文件也会恢复。恢复代码后，所有文件都需要重新读取才能修改。
- **恢复对话**：在存档中追加 `rewind` 记录，退出后再恢复会话时也保持截断。屏幕重新显示保留下来的消息，被退回的消息原文（包括图片）放回输入框。Token 统计和费用不回退。
- 任务运行中不能回退；有后台任务运行时不能恢复代码，提示先等待或用 `/tasks` 停止。
- 空闲且输入框为空时，0.5 秒内连按两次 Esc 也会打开列表。

## 无界面输出

json 与 stream-json 的结果包含 `session_id`。stream-json 的第一条事件是 `{"type": "session", "id": …, "resumed": true/false}`。

## 清理与关闭

- 启动时清理所有项目中 30 天前的存档：`<ID>.jsonl`、同名会话目录和锁文件一起删除。只处理文件名符合 ID 格式的文件；使用中的会话跳过；会话目录仍要求带标记文件 `.mosscode-session`。清理失败时静默跳过。
- 旧版本的位置 `~/.mosscode/sessions/` 不再写入，按原规则清理到全部过期为止。
- 配置 `persist_sessions: false` 时不写存档、不加锁，`/resume`、`--continue`、`--resume` 不可用并说明原因。
