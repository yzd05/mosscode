# 工具与 Agent Loop

本地工具的契约、执行顺序与 Agent Loop 的停止条件。权限见 [permissions.md](permissions.md)。

## 工具

工具默认启用，直接用自然语言要求读取、修改或搜索，例如：“读取 README.md，说明项目入口”，模型自行选择工具。

| 工具 | 行为 |
| --- | --- |
| `read_file` | 以“右对齐行号 + Tab + 原文”格式读取 UTF-8 文本；offset 从 1 开始，limit 默认 2000 行，超过 2000 字符的行截断，翻页提示下一页 offset |
| `write_file` | 创建或覆盖文件，自动创建父目录；覆盖已有文件前须先读取 |
| `edit_file` | 原文精确替换，默认要求唯一匹配；`replace_all: true` 替换全部；须先读取；CRLF 文件可用 LF 原文匹配并保持 CRLF |
| `execute_command` | 在 Git Bash / PowerShell / bash 中执行（见下文），返回 stdout/stderr/退出码；默认超时 120 秒、最大 600 秒 |
| `glob` | 按文件模式查找文件，如 `**/*.py`，支持花括号多选如 `*.{py,md}`、`{src,docs}/**/*`（`grep` 的 `glob` 参数同样支持）；遵守 `.gitignore`，按修改时间从新到旧 |
| `grep` | 按正则搜索内容；`output_mode` 为 `files_with_matches`（默认）、`content` 或 `count`，支持 `glob`、`ignore_case`、`context`、`head_limit` |
| `memory` | 保存或删除跨会话的记忆笔记，只写两个笔记目录，不接受路径；不需要审批，计划模式中也可用。见 [记忆笔记](memory.md#memory-工具) |

## 先读后改

`write_file` 覆盖和 `edit_file` 修改已有文件前，必须在本会话中用 `read_file` 读过它，否则返回 `not_read`；读取后文件被用户、命令或其他程序改动（修改时间或大小变化）时返回 `stale_read`，需重新读取。两种情况文件都不修改；新建文件无需读取，工具自身的写入会更新记录，可连续编辑。修改成功时模型只收到摘要（如“已修改 a.py：替换 1 处，第 12–14 行。”），统一 diff 保存在结果的本地细节中供界面使用，不发送给模型。

## 命令 shell

`config.yaml` 顶层 `shell` 默认为 `auto`——Windows 优先使用 Git Bash（从 PATH 中的 git/bash 和常见安装位置查找，支持 Scoop shim，排除 System32 下的 WSL bash），找不到时使用 PowerShell；其他系统使用 bash，缺失时用 sh。可设为 `bash`、`powershell` 或 bash.exe 的完整路径；明确指定但找不到时启动报错。bash 以 `--noprofile --norc` 启动；Windows 上命令文本通过环境变量 `MOSSCODE_COMMAND` 交给 bash 执行，避免 MSYS 重新解析命令行时把 `\\` 合并为 `\`。系统提示的环境信息、工具描述和界面工具名都显示实际 shell。

## 结果、并发与历史

模型每次完整响应的调用都会执行并写回历史，随后继续请求模型。模型可根据结果选择后续工具或修正参数，直到完整响应不再请求工具。工具结果以纯文本回传模型：成功时是工具输出本身，失败时以 `错误 [code]：` 开头并附原因（例如命令非零退出时附带一次 stdout/stderr，参数校验失败时逐条列出字段）。耗时、退出码等结构化细节只留在本地供界面和测试使用，不重复发送给模型。工具失败不会自动重试，由模型决定下一步。过大的结果在写入历史前存盘，只回传预览（见 [上下文管理](context.md#第一层大结果存盘)）；历史接近上下文窗口时，较早的消息被压缩成摘要。

一次响应包含多个调用时，相邻的只读工具调用（`read_file`、`glob`、`grep`，以及开启 `trust_read_only_hint` 的 MCP 只读工具）最多四个并发，系统提示也鼓励模型把互不依赖的只读调用放在同一次回复中；写文件、改文件、执行命令单独串行。不会把写入后的读取提前执行。界面可先显示较快工具的结果，但工具行和回灌历史始终保持模型原始顺序；Shell 命令统一视为有副作用。

普通对话在完整响应后提交用户与助手消息；工具请求在执行前记录完整调用，并给每个调用配齐结果。取消或断流发生在调用尚未完整接收时，不执行工具；已产生的外部效果不能用“丢弃整轮历史”隐藏。

## 轮数上限与输出截断

默认每个任务最多 200 次模型请求，可用 `config.yaml` 顶层的 `max_iterations` 调整。最后一轮合法调用执行并保存结果后停止，不额外请求最终答复。连续 3 轮全部请求未知工具时停止；含已注册工具的轮次重置该计数。用户取消、断流或协议错误也停止。达到上限后可继续输入推进任务，已完成历史仍保留。

回复达到 `max_output_tokens` 时不当作正常完成：纯文本回复保留已收到的正文并提示“已截断”，可输入“继续”或调高该配置；如果截断发生在工具调用中，参数可能不完整，这些调用不执行，以 `output_truncated` 错误回传模型，循环继续，让模型改为分段输出。默认输出上限为 16384，示例配置按服务给出建议值。

## 计划模式

计划模式只向模型提供只读工具（read_file、glob、grep）、`execute_command`（仅限只读命令）、`memory` 和 `exit_plan_mode`；写入、编辑、非只读命令和外部 MCP 工具返回 `plan_blocked`，任何规则和档位都不能放行。模型调查完成后调用 `exit_plan_mode` 提交 Markdown 计划：计划完整显示在对话中，审批面板提供三项——批准并执行（恢复进入计划前的权限）、批准并自动接受编辑（切换为 acceptEdits）、继续规划（拒绝，模型按反馈修改）。批准后同一任务的下一轮请求即可使用全部工具，无需再次输入。`--prompt` 无界面模式打印计划并返回 approval_required，仍停留在计划模式。输入 `/plan 修复入口报错` 先规划；也可以用 Shift+Tab 或 `/permissions 档位` 手动退出计划模式，再输入要执行的任务。/permissions plan 与 /plan 联动，切换其他权限会退出计划模式。计划保存在当前内存上下文，不建立计划文件。

## 路径、超时与取消

工具相对路径以启动目录为基准，项目内绝对路径也可使用。`read_file`、`glob`、`grep` 可以读取项目目录之外的路径，但需要用户确认（bypassPermissions 直接放行，无界面模式返回 `approval_required`）；写入和编辑始终限于项目目录。命令默认超时 120 秒，可指定正数 timeout，最大 600 秒；等待用户审批不计入执行超时。取消/超时会清理本次命令进程及其子进程。文件写入不可通过取消撤销；如果写入已开始，等待实际结果并保留历史，尚未执行的调用标记未执行。最终模型续答失败也不会丢弃工具结果。

## 搜索与截断

搜索优先使用 PATH 中的 ripgrep（rg），缺失时自动使用独立 Python 搜索进程，无需额外安装才能进行基本搜索。正则语法遵循实际引擎。两种实现都遵守 `.gitignore`（不要求是 git 仓库；回退实现支持注释、`!` 取反、`/` 锚定、目录模式和 `**`）；回退实现的 `glob` 模式与 rg 一样展开花括号（可嵌套，不成对的花括号按字面匹配），`.gitignore` 规则不展开，并跳过 `.git`、`.venv`、`venv`、`node_modules` 和 `__pycache__`；明确指定被忽略的目录作为 path 时仍会搜索。`glob` 和 `grep` 的文件列表按修改时间从新到旧，`glob` 最多 200 项，`grep` 默认 `head_limit` 200 条。命令输出在 2 MiB 处保留开头和结尾、中间标注省略的字节数，这只是内存保护；超过约 12,500 Token 的工具结果（`read_file` 除外）完整存入会话目录，历史中保留开头和结尾的预览，见 [上下文管理](context.md#第一层大结果存盘)。`read_file` 自身分页，超长行有显式截断标记。

## 运行时事件

`AgentLoop` 不依赖界面与 SDK，`Conversation.reply()` 输出异步事件：文字/thinking、完整工具响应边界、工具开始/结果、轮次、用量和停止原因。流式收集器实时转发片段，同时保存完整响应用于后续决策。TUI 和 `--prompt` 共用该运行时。
