# 工具与 Agent Loop

本地工具的契约、执行顺序与 Agent Loop 的停止条件。权限见 [permissions.md](permissions.md)。

## 工具

工具默认启用，直接用自然语言要求读取、修改或搜索，例如：“读取 README.md，说明项目入口”，模型自行选择工具。

| 工具 | 行为 |
| --- | --- |
| `read_file` | 以“右对齐行号 + Tab + 原文”格式读取 UTF-8 文本；offset 从 1 开始，limit 默认 2000 行，超过 2000 字符的行截断，翻页提示下一页 offset；也能查看图片，见下文 [图片](#图片) |
| `write_file` | 创建或覆盖文件，自动创建父目录；覆盖已有文件前须先读取 |
| `edit_file` | 原文精确替换，默认要求唯一匹配；`replace_all: true` 替换全部；须先读取；CRLF 文件可用 LF 原文匹配并保持 CRLF |
| `execute_command` | 在 Git Bash / PowerShell / bash 中执行（见下文），返回 stdout/stderr/退出码；默认超时 120 秒、最大 600 秒；`run_in_background: true` 时在后台运行，见 [后台命令](#后台命令) |
| `glob` | 按文件模式查找文件，如 `**/*.py`，支持花括号多选如 `*.{py,md}`、`{src,docs}/**/*`（`grep` 的 `glob` 参数同样支持）；遵守 `.gitignore`，按修改时间从新到旧 |
| `grep` | 按正则搜索内容；`output_mode` 为 `files_with_matches`（默认）、`content` 或 `count`，支持 `glob`、`ignore_case`、`context`、`head_limit` |
| `todo_write` | 整表更新本次任务的清单，模型用它在多步任务中跟踪进度；不需要审批，计划模式中也可用。见下文 [任务清单](#任务清单) |
| `memory` | 保存或删除跨会话的记忆笔记，只写两个笔记目录，不接受路径；不需要审批，计划模式中也可用。见 [记忆笔记](memory.md#memory-工具) |
| `web_fetch` | 读取一个网页：HTML 转为 Markdown，文本原样返回，其他类型只说明类型和大小；每次约 10,000 Token，用 `offset` 继续读。见下文 [网络工具](#网络工具) |
| `web_search` | 用配置的搜索服务搜索，返回标题、URL 和摘要；只在配置了 `web_search` 且凭据可用时提供。见下文 [网络工具](#网络工具) |

## 先读后改

`write_file` 覆盖和 `edit_file` 修改已有文件前，必须在本会话中用 `read_file` 读过它，否则返回 `not_read`；读取后文件被用户、命令或其他程序改动（修改时间或大小变化）时返回 `stale_read`，需重新读取。两种情况文件都不修改；新建文件无需读取，工具自身的写入会更新记录，可连续编辑。修改成功时模型只收到摘要（如“已修改 a.py：替换 1 处，第 12–14 行。”），统一 diff 保存在结果的本地细节中供界面使用，不发送给模型。

## 命令 shell

`config.yaml` 顶层 `shell` 默认为 `auto`——Windows 优先使用 Git Bash（从 PATH 中的 git/bash 和常见安装位置查找，支持 Scoop shim，排除 System32 下的 WSL bash），找不到时使用 PowerShell；其他系统使用 bash，缺失时用 sh。可设为 `bash`、`powershell` 或 bash.exe 的完整路径；明确指定但找不到时启动报错。bash 以 `--noprofile --norc` 启动；Windows 上命令文本通过环境变量 `MOSSCODE_COMMAND` 交给 bash 执行，避免 MSYS 重新解析命令行时把 `\\` 合并为 `\`。系统提示的环境信息、工具描述和界面工具名都显示实际 shell。命令进程不继承保存 API 密钥的环境变量，见[密钥保护](providers.md#密钥保护)。

命令的输出按行解码：是合法 UTF-8 的行按 UTF-8，其余的行在 Windows 上按系统的 OEM 代码页（中文 Windows 为 936/GBK）解码，所以 `ping`、`ipconfig`、`dir` 等 Windows 程序的中文输出可以正常显示，并可与 Python、Git Bash 工具的 UTF-8 输出混在一起。两种都不符合的行按 UTF-8 解码，无法解码的字节显示为 `�`。其他系统只按 UTF-8 解码。输出过长截断时，截断处被切开的半个字符会被丢弃。

## 后台命令

开发服务器、监视构建和预计要跑几分钟以上的命令可以在后台运行。`execute_command` 带 `run_in_background: true` 时照常审批、照常进入沙箱，启动后立即返回任务 id 和输出文件路径，命令继续运行；可选的 `description`（最多 60 字）是任务标签，缺省为截短的命令文本。工具说明提醒模型不要用 `&`、`nohup`、`Start-Process` 放到后台，这些进程会随命令结束。

- **输出文件**：stdout 和 stderr 按到达顺序写入 `<会话目录>/commands/<任务 id>.log`（不保存会话时写入系统临时目录的 `mosscode-commands/`）。文件由 MossCode 写入，命令不需要写会话目录的权限；模型用 `read_file` 读取，不需要审批。以 `[MossCode]` 开头的行是 MossCode 的说明：转入后台、被拒绝的域名、结束原因。Windows 上输出按[命令输出的解码规则](#命令-shell)转成 UTF-8 后写入（`read_file` 只读 UTF-8 文本）；没有换行的输出最多攒到 4 KiB 再写入。其他系统按原样写入命令输出的字节。
- **结束时**：主对话收到一条 `<task-notification>`，包含任务 id、标签、命令、状态、退出码或被结束的原因、用时、输出文件路径和大小，以及最后 20 行（最多 2,000 字符）。送达方式与 [后台子 Agent 的通知](subagents.md#通知) 相同：主对话空闲时立即开启一轮，忙时在下一次请求前加入。退出码不为 0 时状态为失败。被 `task_stop`、`/tasks stop` 停止，或因 `/clear`、恢复会话、退出而结束的命令不发通知。
- **查看和停止**：`task_output` 返回状态、输出文件和最后 50 行，`wait` 可以等待结束；`task_stop` 结束整个进程树。`/tasks` 列出命令任务，显示输出大小而不是 Token；`/tasks <id>` 显示命令、工作目录、沙箱、输出文件和最后几行。
- **时间限制**：交互界面中默认不限时，模型给出的 `timeout` 就是限制。`-p` 中缺省为 600 秒。时间从启动或转入后台时算起，后台时 `timeout` 最大 3600 秒（前台仍最大 600 秒）。到时命令被结束并发通知。
- **上限**：同时运行的后台命令最多 8 个（配置项 `command_max_background`，0–64），与子 Agent 的 `agent_max_background` 分开计数；达到上限时返回 `too_many_tasks`。设为 0 关闭后台命令，`execute_command` 不再提供 `run_in_background`。
- **输出上限**：输出文件超过 256 MiB 时命令被结束，通知中说明原因。
- **Ctrl+B**：主对话的前台命令运行时按 Ctrl+B，命令转入后台。已收到的输出写进输出文件（stderr 另起一段），之后的输出接在后面；工具结果告诉模型是用户按 Ctrl+B 转入了后台（任务 tN），用户不想等它结束，让模型先继续其他工作或结束本轮、命令结束时再处理通知；前台的 `timeout` 不再生效（`-p` 中照样有 600 秒的限制）。有前台命令时状态栏提示 `Ctrl+B 转入后台`。
- **子 Agent 和团队成员**：它们启动的后台命令在它们结束时一并结束，不发通知，它们自己用 `read_file` 读输出文件。进程内成员的命令也出现在 Lead 的 `/tasks` 中。Ctrl+B 只转主对话的前台命令。
- **会话记录**：主对话记录中为每条命令写开始和结束两条 `{"type": "task"}` 记录（命令、工作目录、输出文件、退出码）；恢复会话不会重新运行旧命令，输出文件保留在会话目录。
- **沙箱**：沙箱中的后台命令各有自己的沙箱实例和代理，到命令结束才关闭。联网不弹审批：没有规则放行的域名被拒绝，并列在输出文件末尾和通知中，见 [命令沙箱](sandbox.md#联网)。在沙箱中启动的服务器从别处连不上：bubblewrap 下只有同一条命令能连接，MXC 和 Seatbelt 下命令不能连接任何本机端口（连它自己启动的服务器也不行），从沙箱外连接也不通；沙箱中的命令也不能连接沙箱外的本机服务。工具说明把这一点告诉模型：要启动并访问的服务器（开发服务器、要连本机端口的测试），服务器和访问它的命令都以 `outside_sandbox: true` 运行，每次由你批准。详见 [命令沙箱的限制](sandbox.md#限制)。
- **状态不保留**：与前台命令一样，每条命令是新的 shell，`cd` 和环境变量不影响之后的命令。
- **已知限制**：Linux 和 macOS 上不开沙箱时，命令中用 `setsid` 等方式脱离进程组的进程不会随命令结束，前台命令也是这样。Windows 上的 Job Object 会结束整棵进程树。

## 结果、并发与历史

模型每次完整响应的调用都会执行并写回历史，随后继续请求模型。模型可根据结果选择后续工具或修正参数，直到完整响应不再请求工具。工具结果以纯文本回传模型：成功时是工具输出本身，失败时以 `错误 [code]：` 开头并附原因（例如命令非零退出时附带一次 stdout/stderr，参数校验失败时逐条列出字段）。耗时、退出码等结构化细节只留在本地供界面和测试使用，不重复发送给模型。工具失败不会自动重试，由模型决定下一步。结果中完整出现的 API 密钥替换为 `[已隐藏的密钥]`（见[密钥保护](providers.md#密钥保护)）。过大的结果在写入历史前存盘，只回传预览（见 [上下文管理](context.md#第一层大结果存盘)）；历史接近上下文窗口时，较早的消息被压缩成摘要。

一次响应包含多个调用时，相邻的只读工具调用（`read_file`、`glob`、`grep`，以及开启 `trust_read_only_hint` 的 MCP 只读工具）最多四个并发，系统提示也鼓励模型把互不依赖的只读调用放在同一次回复中；写文件、改文件、执行命令单独串行。不会把写入后的读取提前执行。界面可先显示较快工具的结果，但工具行和回灌历史始终保持模型原始顺序；Shell 命令统一视为有副作用。

普通对话在完整响应后提交用户与助手消息；工具请求在执行前记录完整调用，并给每个调用配齐结果。取消或断流发生在调用尚未完整接收时，不执行工具；已产生的外部效果不能用“丢弃整轮历史”隐藏。

## 轮数上限与输出截断

默认每个任务最多 200 次模型请求，可用 `config.yaml` 顶层的 `max_iterations` 调整。最后一轮合法调用执行并保存结果后停止，不额外请求最终答复。连续 3 轮全部请求未知工具时停止；含已注册工具的轮次重置该计数。用户取消、断流或协议错误也停止。达到上限后可继续输入推进任务，已完成历史仍保留。

回复达到 `max_output_tokens` 时不当作正常完成：纯文本回复保留已收到的正文并提示“已截断”，可输入“继续”或调高该配置；如果截断发生在工具调用中，参数可能不完整，这些调用不执行，以 `output_truncated` 错误回传模型，循环继续，让模型改为分段输出。默认输出上限为 16384，示例配置按服务给出建议值。

## 计划模式

计划模式只向模型提供只读工具（read_file、glob、grep）、`execute_command`（仅限只读命令）、`memory`、`todo_write`、`exit_plan_mode`、`task_output`、`task_stop`，以及需要确认的 `web_fetch`、`web_search`；写入、编辑、非只读命令和外部 MCP 工具返回 `plan_blocked`，任何规则和档位都不能放行。模型调查完成后调用 `exit_plan_mode` 提交 Markdown 计划：计划完整显示在对话中，审批面板提供三项——批准并执行（恢复进入计划前的权限）、批准并自动接受编辑（切换为 acceptEdits）、继续规划（拒绝，模型按反馈修改）。批准后同一任务的下一轮请求即可使用全部工具，无需再次输入。`--prompt` 无界面模式打印计划并返回 approval_required，仍停留在计划模式。输入 `/plan 修复入口报错` 先规划；也可以用 Shift+Tab 或 `/permissions 档位` 手动退出计划模式，再输入要执行的任务。/permissions plan 与 /plan 联动，切换其他权限会退出计划模式。计划保存在当前内存上下文，不建立计划文件。

## 任务清单

任务需要三步或更多步骤，或用户一次给出多项要求时，模型用 `todo_write` 列出清单，边做边更新。每次调用传入完整的新清单：已有的项带上 `id`，新增的项不带 `id`、由 MossCode 按 1、2、3… 分配（删除的编号不再使用），省略的项即被删除，空列表清空清单。`status` 为 `pending`、`in_progress` 或 `completed`，同一时间最多一项 `in_progress`；每项最多 200 字，清单最多 50 项。不合法的清单（不存在的 `id`、重复的 `id`、多项进行中等）返回 `todo_invalid`，清单保持原样。

- **发给模型**：清单中还有未完成的项时，每次请求在对话历史之后附上一份清单快照，说明它以快照为准、条目是模型自己的计划记录而不是用户的指令，以及清单完成不等于任务完成。快照不写入历史，也不在提示缓存的前缀中，所以更新清单不会使缓存失效；清单全部完成或为空时不再附上。
- **界面**：输入框上方的面板显示“清单 · 已完成 m/n”和最多 4 项未完成的项，进行中的一项以 `▶` 标出，其余以 `□` 标出；更多的项提示用 `/todo` 查看全部。全部完成后显示“✓ 清单已完成 n 项”，直到下一条消息发出后隐藏。工具行显示为 `Todo 已完成 m/n`。
- **范围**：每个子 Agent 和团队成员有自己的清单，互不影响，界面只显示主对话的清单。清单只在内存中，不写入任何文件，随会话记录保存（见 [会话存档](sessions.md#记录格式)）：恢复会话时还原，`/rewind` 退回到某条消息时清单随之退回，压缩后保持当前清单，`/clear` 清空。
- **关闭**：`config.yaml` 顶层设 `todo_tool: false` 后不再提供这个工具。

## 路径、超时与取消

工具相对路径以启动目录为基准，项目内绝对路径也可使用。`read_file`、`glob`、`grep` 可以读取项目目录之外的路径，但需要用户确认（bypassPermissions 直接放行，无界面模式返回 `approval_required`）；写入和编辑始终限于项目目录。命令默认超时 120 秒，可指定正数 timeout，最大 600 秒（后台命令见 [后台命令](#后台命令)）；等待用户审批不计入执行超时。取消/超时会清理本次命令进程及其子进程。文件写入不可通过取消撤销；如果写入已开始，等待实际结果并保留历史，尚未执行的调用标记未执行。最终模型续答失败也不会丢弃工具结果。

## 搜索与截断

搜索优先使用 PATH 中的 ripgrep（rg），缺失时自动使用独立 Python 搜索进程，无需额外安装才能进行基本搜索。正则语法遵循实际引擎。两种实现都遵守 `.gitignore`（不要求是 git 仓库；回退实现用 `pathspec` 按 git 的规则解析，包括转义和深层 `.gitignore` 覆盖外层规则）；回退实现的 `glob` 模式与 rg 一样展开花括号（可嵌套，不成对的花括号按字面匹配），`.gitignore` 规则不展开，并跳过 `.git`、`.venv`、`venv`、`node_modules` 和 `__pycache__`；明确指定被忽略的目录作为 path 时仍会搜索。`glob` 和 `grep` 的文件列表按修改时间从新到旧，`glob` 最多 200 项，`grep` 默认 `head_limit` 200 条。命令输出在 2 MiB 处保留开头和结尾、中间标注省略的字节数，这只是内存保护；超过约 12,500 Token 的工具结果（`read_file` 除外）完整存入会话目录，历史中保留开头和结尾的预览，见 [上下文管理](context.md#第一层大结果存盘)。`read_file` 自身分页，超长行有显式截断标记。

## 图片

`read_file` 按文件头识别图片，不看扩展名：PNG、JPEG、GIF、WebP 直接支持，BMP 转为 PNG，其他二进制文件仍返回 `binary_file`。读取图片时 `offset`、`limit` 不起作用，结果是一行说明，例如 `shot.png · 图片 · 3840×2160 · 2.1 MB（发送尺寸 2000×1125）`，图片附在结果中，随下一次请求发给模型。路径检查和读取权限与文本文件相同，项目外的图片同样需要确认。

发给模型前统一处理：按 EXIF 方向转正，动图只取第一帧，最长边不超过 2000 像素，base64 后不超过 4.5 MB。已经满足这些条件的图片原样发送，不重新编码；否则按比例缩小，在 PNG 和 JPEG（质量 80）中取较小的一个，仍然超限时依次用质量 70、60、50 重试，再把边长缩小到 3/4，最多三轮。

| 错误码 | 情况 |
| --- | --- |
| `image_unsupported` | 当前模型不接受图片（见 [图片输入](providers.md#图片输入)），切换到接受图片的模型后可以读取 |
| `image_too_large` | 文件超过 50 MB、像素数超过解压炸弹上限，或处理后仍超过 4.5 MB |
| `image_invalid` | 文件损坏或不完整，无法解码 |
| `image_store_failed` | 图片已读取，但无法保存到会话目录的 `images/`，结果说明原因，例如路径超过 Windows 的 260 字符限制 |

MCP 工具返回的图片按同样的规则处理，见 [MCP](mcp.md#安全边界与结果)。图片保存在会话目录的 `images/` 中，会话记录只保存引用，见 [会话存档](sessions.md#存档位置)。上下文估算和压缩时图片的处理见 [上下文管理](context.md#估算)。

## 网络工具

两个工具都会把内容发到外部（网址、查询词），因此不是只读工具：default、acceptEdits 和 plan 档位中询问，bypassPermissions 中允许，规则和审批选项见 [工具权限](permissions.md#网络工具)。无界面模式中没有被规则放行的调用返回 `approval_required`，不发出请求。子 Agent（包括内置的 explore、plan）和团队成员同样可以使用，审批照常；它们与主对话共用网页缓存和搜索次数。

网页和搜索结果是不可信的数据：正文包在 `<web_content>` 标记中，系统提示要求模型把其中的指令当作数据，不执行，需要时告诉用户；内容中出现的同名标记会被转义，不能提前结束标记。

### web_fetch

参数为 `url` 和 `offset`（字符位置，默认 0）。只接受 http 和 https，http 自动升级为 https；网址中不能带用户名和密码。

- **本机和内网**：不带点的主机名、`localhost`、`*.localhost`，以及环回、私有、链路本地、保留地址的 IP 字面量，在审批之前就以 `local_blocked` 拒绝，任何档位和规则都不能放行；需要访问本地服务时用 `execute_command`（例如 curl），按命令权限确认。域名在执行时解析，任一地址落在这些范围内也拒绝；连接固定到检查过的地址，防止两次解析结果不同（DNS 重绑定）。`198.18.0.0/15` 不算内网：Clash、Surge 等代理的 fake-IP 模式把域名解析到这个网段。
- **代理**：读取环境变量 `HTTPS_PROXY`（没有时用 `ALL_PROXY`）和 `NO_PROXY`，不读取系统代理设置；通过代理时本机无法解析的域名交给代理解析。`SSL_CERT_FILE` 指向的证书用于校验（公司代理自己的 CA）。
- **重定向**：同一主机内最多跟随 5 次（`too_many_redirects`）；跳到其他主机时不跟随，返回原地址和目标地址，由模型决定是否再读取（新的域名需要再次确认）。重定向到本机和内网同样拒绝。
- **内容**：HTML 去掉脚本、样式、表单等，有 `<main>`、`<article>` 或 `role="main"` 的元素时只取它，否则再去掉导航、页眉、页脚和侧栏，转为 Markdown，相对链接改为绝对地址，图片去掉；纯文本、Markdown、JSON、XML 等原样返回；图片、PDF、压缩包等只说明类型和大小，不下载正文。
- **限制**：最多下载 10 MB（`too_large`），总时长 60 秒（`timeout`）；超出时不返回部分内容。请求头带 `User-Agent: MossCode/<版本>`，`Accept` 优先 Markdown。
- **结果**：开头写明 URL、标题、内容类型、总字符数和本段范围，正文每次约 10,000 Token，尽量在换行处分段；未读完时末尾写明下一段的 `offset`，超出正文长度返回 `invalid_offset`。每个 URL 在本会话中缓存 15 分钟，翻页不重新下载。

其他错误：`invalid_url`（网址格式或协议不对）、`dns_failed`（无法解析域名）、`connect_failed`（连接失败或中断）、`http_error`（非 2xx 状态，附状态码）。

### web_search

参数为 `query`、`allowed_domains` 或 `blocked_domains`（二选一，可选）和 `max_results`（默认 8，最多 20）。返回编号的结果：标题、URL 和摘要（每条最多 500 字符）。不读取结果页面，需要细节时由模型再调用 `web_fetch`。域名过滤同时交给搜索服务并在返回后再检查一次，子域名算在内。

在 `config.yaml` 中配置搜索服务，目前支持 [Tavily](https://tavily.com)：

```yaml
web_search:
  provider: tavily
  api_key_env: TAVILY_API_KEY   # 或者直接写 api_key
```

没有配置或环境变量为空时不向模型提供 `web_search`，`/status` 和 `moss doctor` 显示“未配置”；凭据只显示是否设置，不出现在输出和错误中。每个会话（包括子 Agent 和团队成员）最多搜索 100 次，之后返回 `search_limit`，要求模型用已有信息回答并告诉用户。服务的错误：`search_auth`（凭据被拒绝）、`search_rate_limited`（次数或额度用完）、`search_failed`（超时、连接失败或无法解析返回内容）。

## 运行时事件

`AgentLoop` 不依赖界面与 SDK，`Conversation.reply()` 输出异步事件：文字/thinking、完整工具响应边界、工具开始/结果、轮次、用量和停止原因。流式收集器实时转发片段，同时保存完整响应用于后续决策。TUI 和 `--prompt` 共用该运行时。
