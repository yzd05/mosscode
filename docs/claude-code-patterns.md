# 对照 Claude Code：设计与 MossCode 的实现

MossCode 是学习 Claude Code 后自己写的终端 coding agent。这份文档逐个主题对照：Claude Code 是怎么设计的，MossCode 对应的实现是什么，两者在哪里做了不同的取舍。每个主题只写要点，完整行为见各节末尾链接的参考文档。

Claude Code 一侧依据它的公开文档和实际使用中可观察到的行为，不涉及它的源码；版本更新可能改变其中的细节。

## 1. Agent Loop

**Claude Code**：一个主循环。每次请求带上系统提示、工具定义和历史；回复中有工具调用就执行，把结果追加到历史再请求，回复不再调用工具时本轮结束。没有规划器、路由器或多 Agent 编排层，复杂度放在工具和上下文管理上。

**MossCode**：`agent.py` 是同样的单循环。停止条件明确列出：正常完成、轮数上限（默认 200）、输出截断、连续 3 轮只调用未知工具、取消、错误，每种都以 `RunStopped` 事件告诉界面。空回复和只有思考的截断会丢弃后重发，正文截断后自动续写，最多 3 次。

**取舍**：MossCode 用异步生成器逐个产出事件（文本增量、工具开始与结束、用量、停止原因）。交互界面和 `-p` 消费的是同一串事件，所以两边的行为不会分叉。

见 [工具与 Agent Loop](reference/tools.md)。

## 2. 结构化消息与工具结果

**Claude Code**：历史不是一串字符串，而是带类型的内容块（文本、思考、工具调用、工具结果、图片）。每个工具调用都必须有对应的结果，否则下一次请求会被服务拒绝。

**MossCode**：`messages.py` 定义统一的消息和内容块，`providers.py` 把它映射成三种协议（Anthropic Messages、OpenAI Responses、Chat Completions）。执行工具前先写下完整的调用。取消、断流或崩溃时，未完成的调用也会补上一条说明结果，保证历史总是合法的；恢复会话时也做同样的修复。

**取舍**：工具结果给模型的是纯文本；耗时、退出码、diff 这些结构化细节只留在本地给界面用，不重复发给模型，节省上下文。

见 [结果、并发与历史](reference/tools.md#结果并发与历史)、[会话存档与恢复](reference/sessions.md)。

## 3. 工具设计

**Claude Code**：读、写、改、命令、glob、grep 几个通用工具覆盖大部分工作，搜索类专用工具优先于在命令里调用 `grep` 或 `cat`。工具说明本身就是提示词：什么时候用、不要怎么用，都写在工具定义里。

**MossCode**：本地工具是 `read_file`、`write_file`、`edit_file`、`execute_command`、`glob`、`grep`，加上 `todo_write`、`ask_user`、`memory`、`web_fetch`、`web_search`，以及子 Agent、后台任务、团队相关的工具。每个工具有参数模式和校验，用法规则只放在工具定义里，不在系统提示中重复。相邻的只读调用最多 4 个并发执行；写入和命令串行。

**取舍**：搜索优先用 PATH 中的 `rg`，没有时用内置实现。Windows 上命令优先在 Git Bash 中运行，找不到时用 PowerShell，并按行识别 UTF-8 和 GBK 输出。

见 [工具](reference/tools.md#工具)。

## 4. 先读后改

**Claude Code**：覆盖或编辑已有文件前必须先读过它。`Edit` 要求原文唯一匹配，避免改错位置。

**MossCode**：由工具程序检查，不靠提示词。没读过时返回 `not_read`；读后文件被改过（修改时间或大小变化）时返回 `stale_read`，两种情况都不修改文件。`edit_file` 默认要求唯一匹配，并保留原文件的换行符和编码。

**取舍**：修改成功后，模型只收到一句摘要（第几行改了几处），完整 diff 只给界面看。

见 [先读后改](reference/tools.md#先读后改)。

## 5. 权限在执行路径中

**Claude Code**：权限不是靠提示词约束模型，而是在执行工具之前判定。四个档位是 default、acceptEdits、plan、bypassPermissions；allow、ask、deny 规则按用户、项目、本地分层；审批可以只允许本次，也可以记住。

**MossCode**：同样的四个档位、分层规则文件和三种授权范围（本次、本会话、永久）。命令另有一层风险分级：

- 只读命令白名单，免审批；
- 高风险命令（`git reset --hard`、`rm -rf` 等）每次都要确认；
- 灾难级命令一律拒绝。

可选的命令沙箱由系统限制命令能读、能写、能连接什么：Linux 用 bubblewrap，macOS 用 Seatbelt，Windows 用 MXC 或受限令牌。

**取舍**：路径检查是应用层限制，文档中明确写了它不是沙箱。保存 API 密钥的环境变量不会传给模型执行的命令，工具结果中出现的密钥会被隐藏。

见 [工具权限](reference/permissions.md)、[命令沙箱](reference/sandbox.md)。

## 6. 计划模式

**Claude Code**：计划模式中模型只能读和调查，写完计划后用工具提交；用户批准后，在同一个任务里切回可写的档位继续执行。

**MossCode**：`/plan` 或 Shift+Tab 进入。模型只有只读工具、只读命令和 `exit_plan_mode`，写入一律返回 `plan_blocked`，任何规则都不能放行。批准时有三种选择：批准并执行、批准并自动接受编辑、继续规划。

**取舍**：计划只在内存中，不建计划文件。进入和退出时只发一次模式提醒，放在缓存断点之后，不破坏缓存前缀。

见 [计划模式](reference/tools.md#计划模式)。

## 7. 系统提示与提示缓存

**Claude Code**：系统提示和工具定义构成稳定的前缀，靠提示缓存降低每轮的成本；日期、git 状态这类会变的信息不放进前缀。

**MossCode**：系统提示由七个固定模块组成，后面依次是项目指令和记忆索引，在会话内不变。日期、系统、shell、权限档位和 git 快照放在每次请求末尾的环境补充中。

在 Anthropic 官方端点上有两个缓存断点：稳定系统块的末端，以及最后一个历史块。模式提醒、任务清单快照这类一次性内容都放在断点之后。OpenAI 一类协议依赖服务端的自动缓存。

**取舍**：项目指令和记忆在会话开始时读取一次，中途修改不生效，这是为了保持前缀不变。底栏显示整个会话的缓存命中率。

见 [系统提示与缓存](reference/prompts.md)。

## 8. 项目指令与记忆

**Claude Code**：`CLAUDE.md` 从用户级到项目目录分层加载，可以用 `@路径` 引用其他文件；还有跨会话的记忆。

**MossCode**：

- 指令文件按 `~/.mosscode/AGENTS.md`、从根目录向下每级的 `AGENTS.md`（没有时读 `CLAUDE.md`）、`.mosscode/AGENTS.md` 的顺序加载。
- `@include` 最多展开 5 层，每个文件只能引用自己范围内的文件。
- 记忆是 Markdown 笔记：模型可以用 `memory` 工具写，任务完成后后台也会提取你纠正过的做法。笔记的索引进入系统提示。

**取舍**：后台提取只依据对话，不依据工具输出，防止网页或文件里的内容被写成“用户偏好”。

见 [项目指令](reference/prompts.md#项目指令agentsmd)、[记忆笔记](reference/memory.md)。

## 9. 用量记账与上下文估算

**Claude Code**：上下文占用以服务返回的用量为准，并在界面上提示还剩多少。

**MossCode**：每次回复后以服务返回的 `input_tokens + output_tokens` 为锚点，之后新增的消息按字符估算：ASCII 每 4 个算 1 Token，中文每字算 1 Token。图片按 Anthropic 的公式估算。

服务没给用量时（例如 Chat 协议没开 `stream_usage`）全部按估算。缺失的用量显示为 `—`，部分缺失时显示 `≥`，不编造数字。

**取舍**：不引入分词器。估算有意偏高，宁可早一点压缩，也不要被服务拒绝。

见 [估算](reference/context.md#估算)、[用量](reference/prompts.md#用量)。

## 10. 大结果移出提示

**Claude Code**：很长的工具输出不全部塞进上下文，而是存到文件，上下文里只留预览，需要时再读。

**MossCode**：

- 单个结果超过约 12,500 Token 时，完整内容写入会话目录，历史中只留大小、路径、开头和结尾。
- 同一批并行结果合计超过 50,000 Token 时，从大到小依次存盘。
- `read_file` 本身分页，不存盘；超出预算时在行的边界上缩短。

**取舍**：是否存盘在结果写入历史之前决定，之后不再改写，所以已发送的前缀不变，缓存不受影响。

见 [第一层：大结果存盘](reference/context.md#第一层大结果存盘)。

## 11. 压缩

**Claude Code**：接近上限时自动把较早的对话压缩成摘要，也可以用 `/compact` 手动压缩并指定侧重点；在摘要之前会先清理可以重新获取的旧工具结果。

**MossCode**：自动压缩到期时，先算只清理旧工具结果能腾出多少空间。清理后能降到阈值的一半以下时，只清理不摘要，也不发请求。否则做摘要：

- 摘要按 9 个部分组织；
- 被压缩部分中用户的原话由程序原样附上，不经模型改写；
- 原始消息完整写入 `compact-<n>.md`；
- 连续失败 3 次后暂停自动压缩（熔断）。

**取舍**：清理只发生在本来就要改写历史的时刻，不在每轮常驻检查，避免反复让缓存失效。

见 [第二层：压缩](reference/context.md#第二层压缩)。

## 12. 任务清单与向用户提问

**Claude Code**：模型用 Todo 工具维护多步任务的清单，界面实时显示。需要用户做决定时用提问工具给出选项，而不是在正文里问完就结束本轮。

**MossCode**：

- `todo_write` 每次提交完整的清单。清单快照放在历史之后发送，不写入历史，也不在缓存前缀中，不会在历史里堆出一份份旧清单。
- `ask_user` 一次问 1–4 个选择题，面板出现在输入框的位置。回答作为工具结果返回，本轮直接继续。
- `/goal` 在每轮结束后用另一次模型调用判断目标是否达成，没达成就自动继续。

**取舍**：`ask_user` 只在交互界面的主对话中提供。`-p`、子 Agent 和团队成员没有这个工具，因为没有人能回答。

见 [任务清单](reference/tools.md#任务清单)、[向用户提问](reference/tools.md#向用户提问)、[目标](reference/commands.md#目标)。

## 13. 前台工具与后台任务

**Claude Code**：开发服务器、长时间的构建可以在后台运行，模型稍后查看输出；运行中的前台命令也能转入后台。

**MossCode**：`execute_command` 带 `run_in_background: true` 时立即返回任务 id 和输出文件。命令结束时，主对话收到一条带退出码和最后 20 行的通知；`task_output` 查看，`task_stop` 结束整棵进程树。前台命令运行时按 Ctrl+B 转入后台。

**取舍**：输出写入文件而不是丢弃，模型用 `read_file` 按需读取。Windows 上用 Job Object 保证进程树会一起结束。

见 [后台命令](reference/tools.md#后台命令)。

## 14. 子 Agent

**Claude Code**：子 Agent 在独立的上下文中完成一段工作，只把结论交回主对话，中间输出不占主对话的上下文；Agent 定义是带 frontmatter 的 Markdown 文件。

**MossCode**：有两种子 Agent：

- **定义式**：从空白对话开始，按定义的角色、工具范围和权限档位工作；
- **Fork**：继承主对话到目前为止的全部内容，在后台完成附带的任务。

子 Agent 可以在独立的 git 工作树中运行。更大的任务可以组建 Agent 团队：成员长期存在，通过共享任务和邮箱协作，在 Windows Terminal 或 tmux 的分屏窗格中运行，最后经你确认逐个合并。

**取舍**：子 Agent 的授权从空开始，它得到的授权不会带回主对话。主对话在计划模式时，子 Agent 也一律只读。

见 [子 Agent](reference/subagents.md)、[Git 工作树](reference/worktree.md)、[Agent 团队](reference/teams.md)。

## 15. 扩展：MCP、Skill、Hook、插件

**Claude Code**：

- MCP 接入外部工具；
- Skill 是带说明的可复用规程；
- Hook 在生命周期事件上执行命令或拦截工具调用；
- 插件把这些打包分发。

**MossCode**：四种扩展都有，插件兼容 Claude Code 的格式。设置 `claude_directories: true` 后，也能读取 `.claude/skills/` 和 `.claude/agents/`。

**取舍**：项目里带来的 Hook、插件需要你确认后才启用，`.mcp.json` 默认不读取，因为它们都会以你的权限启动程序。

见 [MCP](reference/mcp.md)、[Skill](reference/skills.md)、[Hook](reference/hooks.md)、[插件](reference/plugins.md)。

## 16. 会话、检查点与回退

**Claude Code**：会话按项目存成追加式记录，可以继续最近的会话或从列表中恢复；改文件前自动做检查点，可以把代码和对话退回到之前的某条消息。

**MossCode**：会话实时写入 `~/.mosscode/projects/<项目键>/sessions/` 下的 JSONL，用 `-c`、`--resume` 或 `/resume` 恢复。`write_file` 和 `edit_file` 改文件前保存检查点，`/rewind` 可以只退回文件、只退回对话，或两者一起退回。

**取舍**：恢复时修复未配对的工具调用，并把中断时没完成的调用标记出来。

见 [会话存档与恢复](reference/sessions.md)。

## 17. 无界面模式

**Claude Code**：`-p` 运行一个任务后退出，输出可以是文本、JSON 或流式 JSON 事件，便于放进脚本和 CI。

**MossCode**：`-p` 和交互界面共用 `Conversation`。需要审批的调用直接返回 `approval_required`，由模型调整做法；`--output-format` 可选 `text`、`json`、`stream-json`。后台子 Agent 照常运行，全部结束后才退出。

**取舍**：未经确认的项目级 Hook 和插件在 `-p` 中不加载，必须显式加参数才信任。

见 [命令行](reference/cli.md)、[无界面模式与输出格式](reference/providers.md#无界面模式与输出格式)。

## 18. 终端界面

**Claude Code**：内联显示在终端中，完成的内容进入终端自己的滚动历史，而不是占用全屏；输入框上下有横线，审批和提问面板出现在输入框的位置。

**MossCode**：用 Textual 实现同样的内联布局。完成的内容写入原生滚动历史，回复边输出边按 Markdown 渲染。启动时查询终端背景色，在浅色和深色两套配色之间选择。

**取舍**：Windows 上有自己的输入线程，因为开启 VT 输入后 Enter 记录不带修饰键，Textual 原来的线程分不出 Shift+Enter。日常开发和验收都在 Windows Terminal 中进行。

见 [终端界面](reference/interface.md)。
