# 同一批读取的合计预算

日期：2026-11-10。状态：已实现，相关测试通过（`tests/test_context.py`）。来源：核对 [向 MiniCode 学习](../../research/minicode-comparison.md) 第二节时发现的缺口。

## 问题

第一层（大结果存盘）已经有两条规则：单个结果超过 12,500 Token 存盘，同一批结果合计超过 50,000 Token 时从大到小存盘。`read_file` 两条都不参与，因为它读的本来就是磁盘上的文件，存盘后再读只会绕回来；它靠单页上限（56 KiB，约 14,000 Token）控制大小。

缺口在于一批里有多个读取时没有合计上限：模型并行读 10 个大文件，约 140,000 Token 一次进入历史。窗口为 128K 的模型会直接超出窗口，而这些内容属于最近的消息，压缩也救不回来。

## 已确认的事实

| # | 事实 |
|---|------|
| F1 | `tool_budget.py` `bound_message` 在一批工具全部结束、结果写入历史时执行一次，之后不再改写，已发送的历史前缀不变 |
| F2 | `read_file` 的输出是若干行“行号 + Tab + 原文”，被分页截断时最后一行是“（共 N 行，还有内容，请从 offset=M 继续读取）”；`details` 中有 `lines`、`total_lines`、`truncated`、`next_offset` |
| F3 | 分页读取只读了一部分也算“读过”（`FileState` 只记录文件，不记录行范围），之后可以编辑；编辑仍要求原文唯一匹配 |
| F4 | 界面的工具行在每个调用结束时显示，早于合计预算的判断；因合计预算而存盘的结果目前也不在工具行上注明 |

## 需求

| # | 要求 | 验收 |
|---|------|------|
| R1 | 一批结果合计超过 50,000 Token 时，先缩短 `read_file` 的结果：读取可用的预算是 50,000 减去其他结果的合计，按平均份额分配，不超过份额的读取保持完整，超过的缩短到份额（注水法） | 10 个各约 14,000 Token 的读取：合计不超过 50,000，每个约 5,000 Token |
| R2 | 缩短在行的边界上进行，至少保留一行；结尾换成“（共 N 行；同一批读取的内容合计超出上下文预算，此文件只保留到第 K 行，请从 offset=K+1 继续读取）”，`details` 的 `lines`、`truncated`、`next_offset` 随之更新 | 缩短后的结果按提示的 offset 再读，与缩短前的内容逐行衔接 |
| R3 | 每个读取至少保留 2,000 Token，读取个数很多时合计可以超过预算（25 个以上的大文件同批读取才会出现） | 单元测试 |
| R4 | 读取缩短后仍超出时，其他结果照原规则从大到小存盘；没有读取的批次行为不变 | 现有测试不变 |
| R5 | 小文件、图片、出错的读取不受影响；缩短只做一次，再次执行不改变结果 | 单元测试 |

## 设计

- `bound_message` 中，现有的存盘循环之前增加一步：找出本批中成功的 `read_file` 结果，按 R1 算出份额，对超过份额的调用 `shorten_read`。
- `shorten_read` 按“行号 + Tab”解析输出，累计到份额为止，从最后保留的行号得到下一页的 offset；`details` 中写入 `budgeted`，与存盘的结果相同，表示不再处理。
- 先缩短读取、后存盘其他结果：缩短读取没有信息损失以外的代价（不写磁盘，模型按 offset 接着读即可），其他结果因此更可能保持完整。

## 真实模型验收

2026-11-10，DeepSeek（项目 `config.yaml` 中配置的 Provider），`-p --output-format stream-json`：要求在一次回复中并行读取 `src/mosscode` 下 6 个文件（合计约 71,000 Token）。模型一次发出 6 个 `read_file`，随后说明“批量读取时内容超出上下文预算”，按提示的方式用 offset 再读了 `conversation.py` 的末尾，6 个文件的总行数和最后一个方法名都回答正确；共 3 次请求，输入合计约 118,000 Token。

## 不做

- **按窗口大小调整预算**：50,000 是现有规则的数值，本次沿用。
- **界面工具行和 `stream-json` 的 `tool_result` 注明缩短**：它们在每个调用结束时输出（F4），显示的是缩短前的结果，与因合计预算存盘的结果一致，暂不处理。
