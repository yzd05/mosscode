## 现状

- 默认系统提示（含六个本地工具）约 2,860 字符，其中约 1,300 字符是“使用指导”：各工具的 `prompt_guidelines`。同一份指导又追加在 API 工具描述（`Tool.definition()`）中，因此**每次请求发送两遍**。
- 七个模块中有重复表述：权限与授权在“系统约束”和工具指导中各说一次；“未验证”在“系统约束”和“文本输出”中各说一次；计划模式规则在“任务模式”模块和模式提醒中各说一次。
- 执行层已经把相邻的只读工具调用（`read_file`、`glob`、`grep`、受信任的 MCP 只读工具）分批并发执行，每批最多 4 个（`tools/execution.py`）。但提示中没有提到这一点，模型很少在一次回复中发出多个独立调用。
- 提示中没有明确要求简洁回复、不复述计划。
- README 共 325 行，混合了安装、使用和各章实现细节（重试算法、缓存断点、路径检查、MCP 传输细节等），还有已经过时的章节说明（如“第四章规格…”、“此轮只增加…第十章”）。

## 设计

### 系统提示（`src/mosscode/prompts.py`）

- 保留七个模块及其名称和顺序（identity、constraints、mode、execution、tools、tone、output），只重写文字。
- `build_system_prompt` 不再生成“使用指导”段落；工具模块 = 通用说明 + “当前可用工具”清单。`ToolDefinition.prompt_guidelines` 保留，`Tool.definition()` 仍把它们追加到描述中，MCP 和自定义工具不受影响。
- 工具模块写明并行规则：“互不依赖的只读调用一起发出”。是否真的并发由执行层按 `read_only` 决定，提示不承诺具体并发数量。
- 计划模式的细节（可用工具清单）只保留在模式提醒和工具定义中，“任务模式”模块保留一句概要。

**取舍：规则放在工具描述还是系统提示。** Pi 把工具指导放在系统提示，Claude Code 放在工具描述。这里选择工具描述：
- 模型调用工具时正好看到它；
- 自定义 `system_prompt` 时规则不会丢失；
- MCP 等外部工具本来就只有描述。

两种位置都在缓存前缀中，删掉其中一份不影响缓存命中。
