# MCP 配置快照、安装验收与共享调用预算

日期：2026-11-13。状态：已实现。基线：`de4361c`。

## 目标与范围

本轮沿用现有 Agent Loop、Conversation、Hook、会话记录和测试夹具，完成交接包中已确认的增量。代码、注释用英文，面向用户的说明用中文；只为改变的行为和安全边界增加测试。

- MC01：修复审批后重新读取项目 MCP 配置的问题。
- MC03：安装 wheel 后在源码目录之外完成不联网的受控任务。
- MC04：主 Agent、子 Agent、Skill fork、辅助模型调用和进程内团队成员共享本次运行的模型调用预算。
- MC05：验证压缩后用户纠正、目标和任务清单仍可送达，不改动清理/折叠/摘要策略。
- MC07：验证外部内容提取边界，并为已载入笔记的更新、删除补充下一次请求的失效提醒。

真实模型评测、RSI、任务数据库、统一交付系统和独立架构重构不在本轮范围。现有诊断行为只随本轮涉及的路径调整。

## 已确认的现状

- `confirm_project_mcp` 返回是否允许项目服务器，随后 `load_mcp_settings` 会重新读取项目文件。审批期间把命令 A 改为 B，会出现批准 A 后加载 B；此前已用零进程的临时夹具复现。
- 发布已等待同一提交的完整 CI；wheel 安装后仅检查帮助和版本。
- 模型用量已汇总，循环、后台数量和命令时间已有各自上限，但主子 Agent 没有共享的调用额度。
- 压缩会重发模式、goal、todo 提醒并清除文件读取状态，保留用户原话。
- 记忆索引在会话加载时固定。写入会更新磁盘索引，但当前会话没有统一的已载入内容失效提醒。

## 行为要求

| 要求 | 行为 | 必要验收 |
| --- | --- | --- |
| MCP 快照 | 项目 YAML 和导入 JSON 各读一次，解析、摘要、审批和本次加载使用相同字节；用户拒绝时保留用户级服务器 | 审批期间替换 YAML/JSON 后，本次仍只加载审批过的配置；下一次启动再次询问 |
| MCP 兼容 | 复用现有信任记录和展示，环境变量仍按原规则展开；不重新批准磁盘程序或远端服务本身 | 现有信任、导入、同名覆盖测试通过 |
| wheel 冒烟 | 在包外目录以安装后的 Python 运行假 Provider 对话，读取并修改夹具文件，检查结果与内置 Skill 资源 | CI 对 wheel 调用受控任务；无需配置、凭据或真实模型 |
| 共享预算 | 新增 `run_budget`，`requests`、`tokens` 为非负整数，0 不限制；默认关闭 | 主子 Agent 的请求合计受同一个额度约束，摘要等辅助调用计入 |
| 额度语义 | 作用域为本次启动到退出；切模型、恢复、`/clear` 不重置。请求额度在调用前占用；Token 在服务返回用量后累计，达到额度后不再发新请求 | 恰好耗尽时不发生额外调用；并发领取不超请求数 |
| 未知用量 | 开启 Token 额度时，如服务未报告完整用量或流未正常完成，停止后续请求并说明无法继续核算；不声称限制了在途费用 | 未知用量不能被当成 0 绕过 |
| 团队预算 | 开启预算时，auto 选择进程内成员；显式窗格后端说明不支持共享额度并拒绝创建，不悄悄让成员脱离预算 | 后端选择与共享对象各验证一次 |
| 预算结束 | 沿用 ProviderError 和现有错误/目标暂停处理；已启动命令沿用原超时和停止规则。运行预算是模型调用额度，不是整个系统的 CPU 或费用硬上限 | 保留已执行历史，不把额度耗尽标为完成 |
| 上下文保真 | 用现有模拟 Provider 验证摘要后最新用户纠正、运行时目标和未完成清单仍在下一请求中 | 复用上下文测试夹具增加组合场景，不重复测试已有分页、格式和界面行为 |
| 记忆失效 | 更新或删除笔记后，不改写系统提示前缀；下一次模型请求收到一次提醒，旧内容须重新读取，笔记不改变用户授权 | 更新/删除与后台提取沿用相同提醒路径；不自动开启新一轮 |

## 实现位置

- `mcp_config.py` 保存项目配置快照，CLI 将确认过的快照传给加载函数；doctor 等只读调用保持原用法。
- `limits.py` 用一个小型共享额度对象和流函数统一占用请求与收集用量，不包装或替换 Provider 的其余接口。
- `agent.py`、摘要、目标判断和记忆提取通过同一流函数发起请求；子 Agent 和进程内成员共享父额度对象。
- `Conversation` 接收预算配置并组装，不增加另一套任务管理器。
- 安装验收脚本在 CI 的 wheel 环境中运行；使用标准库假模型，不下载依赖、不发网络请求。
- 记忆提醒复用现有一次性 reminder 机制，与恢复/回退提醒合并。
