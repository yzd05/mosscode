# 第三章：工具系统

状态：需求已确认，已实施。2026-10-09 用户接受建议方案并授权直接执行。本文件集中记录规格、设计、任务和验收，不引入额外审批阶段。验证记录见同目录 validation.md。

## 目标与现状

在 MossCode 第二章的流式对话基础上接入六个本地工具：读文件、写文件、精确修改文件、执行命令、查找文件、搜索内容。模型选择工具和参数，运行时执行，Provider 转换协议，TUI 展示过程与结果。

现有实现支持 Anthropic Messages、OpenAI Responses、OpenAI Chat Completions，三者都要扩展工具能力。现有官方端点、第三方兼容端点、命名 Provider、凭据配置、流式正文、thinking、Markdown 和历史滚动行为继续使用。

本章完成工具反馈的一次执行阶段：工具结果之后额外生成一次禁用工具的最终文本答复。每次输入最多两次模型请求，不实现反复请求模型和执行工具的 Agent Loop。

参考资料用于理解实现取舍，不作为额外要求。MewCode 实战文档开头的“一次结果就停下”与其后正式规格的“单轮闭环 + 续答”存在区别，MossCode 需要明确选择。

## 已确认的决策

| 决策 | 确认方案 | 对实现的影响 |
| --- | --- | --- |
| 工具结果后的停止点 | 工具执行后再请求一次模型，明确禁用工具，输出最终答复后停止 | 每次用户输入最多两次模型请求、一次工具执行阶段 |
| 同一次响应中的多个调用 | 按响应中出现的顺序串行执行全部调用 | 不是多轮 Agent Loop；所有调用必须有匹配的结果，不能无声丢弃剩余调用 |
| 文件操作范围 | 相对启动目录解析相对路径，接受绝对路径 | 不在本章增加路径白名单或权限确认；命令具有当前用户的系统权限，文件路径限制不能作为命令沙箱 |

用户已整体接受上述方案，无未决的实现方向问题。

## 已明确的行为

1. 六个工具实现同一接口：工具名称、描述、参数 JSON Schema、异步执行入口。注册中心拒绝重复名称，按名查找并导出统一工具定义。
2. 参数只在完整拼接后解析、校验和执行；流式显示工具信息不等于执行。模型响应未完整结束时不启动写入或命令等副作用。
3. 工具失败返回结构化结果，不让单个工具失败终止会话：包含成功/失败标识、输出、错误代码和适用的元信息。
4. 无效 JSON 不能悄悄替换成空参数。未知工具、缺失字段、类型错误、文件不存在、匹配数错误、命令非零退出与超时分别有明确反馈。
5. 搜索无结果是成功的空结果。用户可继续下一轮，模型随后自行调整；本章不自动重试工具。
6. 三种协议内部统一表达工具调用及其结果，通过调用 ID 配对。厂商 SDK 类型留在 Provider 边界。
7. 延续当前 Esc 取消、Ctrl+Q 退出和历史滚动。工具引入外部副作用后，不能继续沿用“取消即整轮回退”的简单规则。
8. 会话仍仅保存在内存；不加持久化、上下文压缩、热切换 Provider 或完整命令框架。

## 六个工具的拟定契约

参数名与默认值属于本章实现设计；相对路径以启动目录为基准，接受绝对路径。

| 工具名称 | 参数 | 行为与结果 |
| --- | --- | --- |
| `read_file` | `path`，可选 `offset`、`limit` | UTF-8 文本读取，行号从 1 开始；默认读取前 200 行，明确说明截断与下一段起点；不存在、目录、二进制或解码失败返回错误 |
| `write_file` | `path`、`content` | 写入 UTF-8 文本，可覆盖已有文件，自动创建父目录；同目录临时文件完成后替换目标，返回写入摘要，不假装取消能撤销已完成写入 |
| `edit_file` | `path`、`old_text`、`new_text` | 按原文精确且唯一匹配替换；禁止空 `old_text`；0 次或多次匹配都返回匹配数并保持原文件；保留未修改部分的换行符 |
| `execute_command` | `command`，可选 `cwd`、`timeout` | Windows 默认使用 PowerShell（优先 pwsh，回退 Windows PowerShell）；其他系统使用系统 shell。返回 stdout、stderr、退出码、耗时与截断标记；默认超时 30 秒，上限 120 秒 |
| `glob` | `pattern`，可选 `path` | 查找匹配的文件，支持递归模式，稳定排序；默认跳过版本库内部目录、虚拟环境、依赖与缓存目录；空列表是成功 |
| `grep` | `pattern`，可选 `path`、`glob` 文件模式过滤 | 搜索文本内容并返回路径、行号和匹配行；不把用户参数拼成 shell 命令；无结果成功，非法模式明确报错；优先复用 rg，缺失时使用受超时保护的独立 Python 搜索进程 |

读文件与搜索的分页、结果上限只限制单次工具返回，不删除会话历史，也不改变模型配置的上下文窗口。命令输出保留固定上限的 stdout/stderr，并在输出超过上限时继续排空管道，避免进程阻塞；截断必须显式标明。

实现上限：每路命令输出最多 32 KiB，搜索最多 200 个结果，单次文本结果最多 64 KiB。读取文件按字节预算提前结束页，next_offset 指向尚未显示的下一行；单行过长时明确说明行内截断。工具超时是独立于现有 Provider 网络 `timeout` 的执行约束。rg 缺失时回退到 Python 正则：基础搜索行为一致，高级正则语法遵循对应引擎。

## 模块职责与数据流

### 工具模块

新增 `src/mosscode/tools/`，内部包含工具接口、参数模型、注册/执行入口，以及文件、命令、搜索的具体实现。已有 Pydantic 依赖由 SDK 间接安装；如果采用参数模型自动导出 Schema，将其声明为项目直接依赖，避免依靠 SDK 的间接依赖。

注册中心导出协议无关的 `ToolDefinition`；Provider 再转换成各 API 的工具列表。不让文件工具知道 Anthropic、OpenAI 或终端组件。

执行边界统一处理参数校验、工具查找、时间限制、异常转换和执行事件。取消信号不能被当作普通工具异常吞掉。命令超时/取消需结束由本次调用启动的进程树，并等待清理；禁止终止无关进程。Windows 使用带启动门控的 Job Object，分配完成后才启动实际命令，关闭时回收全部所属进程；其他系统使用独立进程组。

普通文件系统操作放在线程中，不冻结界面。Python 不能强制停止进行中的文件 I/O；取消或超时时先等待已开始的文件操作结束、记录实际结果，再停止后续调用，必要时在结果中标注 deadline_exceeded。这不是文件事务，也不承诺网络文件系统挂起时能按秒强制返回。搜索回退在独立进程内运行，可终止超时正则，不在界面线程执行。

### 消息与 Provider

扩展 `src/mosscode/messages.py`：统一工具定义、工具调用（ID、名称、原始参数）、工具结果以及运行事件。保留现有文本/thinking块和同协议原生签名/加密数据。

流式参数以调用索引/ID 分别积累，不能用单一全局 JSON 缓冲承接多个调用。调用完成事件只通知状态；执行仍等待该模型响应正常完成。相同 ID 的重复完成通知不能重复执行。

`src/mosscode/providers.py` 接收统一工具列表，可控制最终续答阶段禁用工具。协议映射：

| 协议 | 模型调用 | 结果回放 |
| --- | --- | --- |
| Anthropic Messages | `tool_use` 内容块、`input_json_delta`，保留同一 assistant 中的文字与 thinking | 后续 user 内容块里的 `tool_result`，使用 `tool_use_id` 和 `is_error`；成批结果一起发送 |
| OpenAI Chat Completions | `delta.tool_calls`，按 index 拼接名称、ID 和 arguments | assistant 的 `tool_calls` 后接 `role=tool` 的结果，使用 `tool_call_id`；兼容服务返回的必要 reasoning 数据保留 |
| OpenAI Responses | `function_call` 输出项和对应参数增量，区分 item ID 与 call ID | 回放原 assistant 输出项，随后发送 `function_call_output`，使用 call ID 配对，保留必要加密 reasoning |

旧式 `function_call` 不偷偷转换为没有可靠 ID 的调用；不兼容内容明确报错。兼容服务是否实现工具能力由实际响应决定，不加入 Provider/model 白名单。

### 单次编排与历史

复用现有 `Conversation` 作为会话拥有者，抽出一次工具执行阶段的编排逻辑，避免 TUI 驱动工具或 Provider 执行本地命令。暂不搭建完整 Agent 框架。

无工具的响应沿用原逻辑：用户消息和完整 assistant 成对提交。

有工具时，历史从简单的 user/assistant 对，扩展为：用户输入 → assistant 工具调用 → 所有对应工具结果 → 可选最终 assistant 文本。

副作用边界：

- 模型流未完成、工具尚未开始：取消/断流不执行工具、不提交未完成调用。
- 完整调用已接收，执行即将开始：记录用户消息及完整 assistant 调用；每个调用最终都要补齐成功、失败、取消或未执行结果。
- 工具已经执行：即使用户取消或最终续答失败，也保留已执行调用及结果；不把它们从模型历史抹掉。尚未启动的调用补齐“未执行”结果；不再启动新调用。
- 最终文本响应失败：部分文本保留在界面并标注，但不作为完成 assistant 记录；已提交工具历史保留供下一轮使用。

若选择最终续答：只再发起一次禁用工具的请求。兼容服务忽略禁用设置仍返回工具调用时，不执行，将额外调用配齐明确的未执行结果并展示本章上限提示；禁止留下悬空工具调用或再次请求。

### TUI 与 CLI

在已有历史区显示 Claude Code 风格的简洁工具行：`● Read(path)` / `● Edit(path)` / `● PowerShell(command)`，结果用缩进的 `└` 摘要。原生终端背景、普通文字亮度、浅绿色 Logo、输入位置和蓝色命令候选保持现有约定。

工具正在解析、执行与完成的状态可区分，显示耗时，失败显示明确原因；过长输出只展示有标记的摘要，不铺满对话区。错误不会伪装成助手成功答复。

不新增独立全屏工具页、点击执行按钮、花哨配色、可折叠工具详情或工具权限弹窗。沿用流式正文、结束后 Markdown 格式化、thinking 完成后收起与历史滚动。无界面 `--prompt` 入口使用相同编排并能显示工具结果，不能把带工具但无正文的响应当作空白成功。

## 范围控制

本章不复制参考代码的延迟工具发现、ToolSearch、文件缓存门控、并行执行标记、MCP、Hook、Skill、权限系统或自动修复循环。只引入本章确实使用的抽象与元信息。

借鉴 harness 思路的具体落点：协议适配、工具执行、会话状态、取消和终端展示职责分开；六个工具复用同一执行边界；结果按原调用配对并进入规范历史。第三章先验证这个边界，第四章再增加循环。

资料核对：已通过 Context7 查询 OpenAI Python SDK 和 Anthropic Python SDK 的当前工具流式事件与结果格式，实施时仍需结合已安装 SDK 核对类型与本地模拟请求。参考 MewCode 离线第三章，相关章节仅作为学习资料，不继承其与本项目现有取消功能冲突的“不支持取消”限制。
