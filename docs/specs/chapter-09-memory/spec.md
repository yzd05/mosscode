# 第九章：记忆与会话持久化（总览）

日期：2026-10-24。状态：用户已确认（2026-10-24，见“已确认的决定”），按 9a → 9b → 9c 实施。

来源：用户的初步设计（项目指令文件、会话存档、自动笔记三套机制；JSONL 追加写；四类笔记；索引 200 行 / 25 KB），以及 2026-10-24 对该设计的评审意见（排序方向、JSONL 与压缩的冲突、存档位置、记忆投毒）。用户已确认按评审调整后的方案拆成三个子阶段。

## 目标

新会话启动时自动恢复项目知识和用户偏好，中断后可以接着之前的对话继续工作。Agent 从“每次失忆”变成“越用越懂你”，同时不降低现有的权限和安全边界。

| 记忆层 | 内容 | 谁来写 | 生命周期 | 子阶段 |
| --- | --- | --- | --- | --- |
| 项目指令 | 技术栈、代码规范、注意事项 | 用户手写 | 长期，随仓库或用户目录 | [9a](9a-instructions.md) |
| 会话存档 | 一次会话的完整消息 | 程序自动追加 | 30 天 | [9b](9b-sessions.md) |
| 自动笔记 | 用户偏好、纠正反馈、项目知识、参考资料 | 模型（主循环工具或后台提取） | 长期，可修改和删除 | [9c](9c-auto-memory.md) |

## 存储布局

```
<项目>/
├── AGENTS.md（或 CLAUDE.md）           9a：项目指令，已有
└── .mosscode/AGENTS.md                 9a：新增，MossCode 专用的项目指令

~/.mosscode/
├── AGENTS.md                           9a：用户级指令，已有
├── memory/                             9c：用户级笔记
│   ├── MEMORY.md                       索引（程序生成）
│   └── <slug>.md
├── projects/<项目键>/
│   ├── sessions/
│   │   ├── <会话 ID>.jsonl             9b：会话存档
│   │   ├── <会话 ID>.lock              9b：使用中的锁
│   │   └── <会话 ID>/                  第八章的会话目录（存盘结果、压缩记录），位置迁移到这里
│   └── memory/                         9c：项目级笔记，结构同用户级
└── sessions/                           第八章的旧位置：不再写入，只继续清理
```

- **项目键**：启动目录 `resolve()` 后的路径（Windows 上先转小写），把非字母数字字符替换为 `-`，取末尾最多 48 个字符，再接 `-` 和路径 SHA-256 的前 8 位十六进制。例如 `F--code-storage-PyCharm-MossCode-1a2b3c4d`。可读部分方便人查找，哈希避免 `a-b` 与 `a/b` 撞车。
- **会话 ID**：`YYYYMMDD-HHMMSS-xxxx`（4 位十六进制随机串），与第八章 `Session.create` 相同。创建文件时使用独占模式，撞车就重新生成。
- 会话存档和笔记都放在用户目录，不写入项目，不会出现在 `git status` 和搜索结果中，也不会被误提交。需要与团队共享的知识写进手写的 AGENTS.md。

## 共享原则

| # | 原则 |
| --- | --- |
| P1 | **系统提示在会话内冻结**：项目指令（含展开后的 @include）和笔记索引只在启动、`/clear`、恢复会话时加载。会话中途文件变化或新写入的笔记，下次加载时才生效。稳定前缀逐字节不变，Prompt Cache 保持有效（与第八章 L3 同理） |
| P2 | **背景，不是指令**：项目指令、笔记和恢复的历史都不能覆盖系统约束与权限规则。注入时明确写出这一点 |
| P3 | **不恢复授权**：恢复会话只恢复对话内容。权限档位、“本会话允许”的规则、计划模式和 `FileState` 都不恢复 |
| P4 | **记忆只来自用户**：自动笔记只依据用户消息和模型的回复提取；工具结果（文件、命令输出、MCP、网页）不能成为笔记来源。防止外部内容通过记忆长期影响之后的会话 |
| P5 | **不保存凭据**：笔记写入前过滤疑似凭据。会话存档会包含工具输出，只放在用户目录，并在文档中说明 |
| P6 | **少一份状态**：不维护单独的 meta 文件。会话的标题和消息数从 JSONL 计算；笔记索引从各笔记的 frontmatter 生成 |
| P7 | **崩溃安全**：所有写入要么是一次完整的追加行，要么是“写临时文件再 `os.replace`”，中途崩溃不会留下半个文件 |

## 配置项汇总

| 选项 | 默认 | 子阶段 | 说明 |
| --- | --- | --- | --- |
| `persist_sessions` | `true` | 9b | 关闭后不写会话存档，`/resume` 不可用；第八章的存盘结果和压缩记录照常写入 |
| `memory` | `true` | 9c | 关闭后不注入笔记、不提供 `memory` 工具、不做后台提取 |
| `auto_memory` | `true` | 9c | 只控制后台提取；关闭后模型仍可在用户要求时用 `memory` 工具记录 |
| `memory_provider` | 无 | 9c | 后台提取使用的 Provider 名称；未设置时使用当前 Provider |

## 已确认的决定（2026-10-24）

以下各项均按推荐值确认，各子阶段规格据此编写。

| # | 问题 | 决定 | 未采用的备选 |
| --- | --- | --- | --- |
| Q1 | 项目级笔记放在哪里 | 用户目录 `~/.mosscode/projects/<项目键>/memory/`，是个人笔记，不进仓库 | 项目内 `.mosscode/memory/`，可以随仓库提交共享，但自动生成的内容容易被误提交，也会被搜索到 |
| Q2 | 恢复会话后的时间跨度提醒阈值 | 距上次活动 ≥ 6 小时 | 固定 1 小时，或做成配置项 |
| Q3 | `-p` 无界面模式是否做后台提取 | 不做：脚本调用不应产生额外请求，进程也很快退出 | 退出前同步提取，最多等待 30 秒 |
| Q4 | 计划模式中能否使用 `memory` 工具 | 可以：它只写用户目录中的笔记，不改项目文件 | 计划模式中不可用 |
| Q5 | 后台提取是否默认开启 | 开启，并在对话中显示每次更新的笔记，让用户看得见 | 默认关闭，由用户在配置中开启 |

## 不做

向量数据库、RAG 检索、团队记忆同步、会话的跨设备同步、会话分支与重命名、存档加密、笔记的自动过期删除（由提取器或用户删除）、恢复会话时恢复最近读过的文件内容。
