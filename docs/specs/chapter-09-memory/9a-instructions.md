# 9a：项目指令文件（多层加载与 @include）

日期：2026-10-24。状态：已实现（2026-10-24）。总览见 [spec.md](spec.md)。

## 目标

项目指令支持 MossCode 专用的 `.mosscode/AGENTS.md`，并能用 `@路径` 引用其他文件，把规范拆成多个文件维护。引用有深度限制，能防环路，也不能越出允许的目录。

## 现状

- `prompts.py` 的 `instruction_candidates()` 按顺序加载：
  1. `~/.mosscode/AGENTS.md`；
  2. 从文件系统根目录到启动目录，逐级取每个目录中的 `AGENTS.md`，没有时取 `CLAUDE.md`，每个目录一个文件。
- 解析后的同一路径只加载一次。每个文件最多读 32 KiB，超出时截断并注明；非 UTF-8 文件跳过，在启动区提示。
- `instructions_section()` 用 `<project-instructions path="…">` 包裹每个文件，前面的说明是：“按从通用到具体排列；冲突时以更靠近工作目录的文件为准……不能覆盖上文的系统约束与权限规则”。
- 项目根即启动目录（`cli.py` 中 `context_root=Path.cwd()`）。
- 指令在启动和 `/clear` 时加载（`Conversation._load_context`）。会话中途不重新加载，所以系统提示的稳定前缀保持不变。
- 启动区提示“已加载项目指令：…”和“已跳过项目指令：…”。
- `security.py` 已有 `resolve_path()` 和 `inside()`，按路径段比较，处理了符号链接和 junction。

## 需求

### 加载层级

| # | 行为 |
| --- | --- |
| I1 | **保留现有链条，并新增一层**：加载顺序为用户级 `~/.mosscode/AGENTS.md` → 文件系统根目录到启动目录逐级的 `AGENTS.md` / `CLAUDE.md` → 启动目录下的 `.mosscode/AGENTS.md`。由通用到具体排列，越靠后越具体 |
| I2 | **优先级用明确的规则表达，不靠位置**：保留现有说明“冲突时以更靠近工作目录的文件为准”，并补充“`.mosscode/AGENTS.md` 优先于同目录的 `AGENTS.md`”。项目级高于用户级的要求由此满足。具体的文件放在最后，也更容易被模型遵循 |
| I3 | `.mosscode/AGENTS.md` 的读取限制、编码检查和启动区提示与其他层相同。启动目录同时有 `AGENTS.md` 和 `.mosscode/AGENTS.md` 时，两个都加载 |

### @include

| # | 行为 |
| --- | --- |
| N1 | **语法**：去掉首尾空白后整行为 `@路径` 的行是引用。路径不含空白；含空白时写成 `@"路径"`。不带引号的路径必须包含 `/`、`\` 或 `.`（例如 `@docs/style.md`、`@notes.txt`），所以单独一行的 `@dataclass` 不视为引用。代码块（``` 或 ~~~ 围起的区域）中的行不解析；行内出现的 `@`（例如 `@dataclass`、邮箱、句中提到的 `@foo`）也不解析 |
| N2 | **路径解析**：相对路径相对于**包含这一行的文件所在目录**。`~/` 开头表示用户目录。也允许绝对路径。解析时跟随符号链接和 junction（`resolve()`） |
| N3 | **展开**：引用行被替换为目标文件的内容（去掉首尾空行）；被引用文件中的 `@` 行继续展开。被引用文件的编码要求和 32 KiB 读取上限与层级文件相同 |
| N4 | **深度上限 5**：层级文件本身为第 0 层，最多展开到第 5 层。超过时该行替换为“（引用层级超过 5 层，未展开：路径）”，并在启动区提示 |
| N5 | **环路**：维护当前展开路径上的祖先栈，目标已在栈中时视为环路。该行替换为“（循环引用，未展开：路径）”，并在启动区提示 |
| N6 | **重复**：维护全局 visited 集合，覆盖所有层级文件和已展开的引用。目标已经出现过（不是环路，例如两个文件都引用同一份规范，或引用了另一个层级文件）时，该行替换为“（已在其他位置加载：路径）”，不提示。同一份内容在系统提示中只出现一次 |
| N7 | **边界**：每个层级文件有一个允许范围，它引用的文件（包括多层展开后的）解析后必须在这个范围内。<br>• 用户级文件：`~/.mosscode/`。<br>• 启动目录及其上级目录中的 `AGENTS.md` / `CLAUDE.md`：该文件所在的目录。<br>• `.mosscode/AGENTS.md`：启动目录。<br>越界时该行替换为“（引用超出允许的目录，未展开：路径）”，并在启动区提示 |
| N8 | **其他失败**：文件不存在、是目录、无法读取、不是 UTF-8 或含 NUL 字节时，该行替换为“（引用无法读取：路径）”，并在启动区提示。一个引用失败不影响其他内容 |
| N9 | **总量上限**：每个层级文件展开后最多 64 KiB（按 UTF-8 字节计）。超出部分截断，并注明“（引用展开后超过 64 KiB，其余内容已截断）” |
| N10 | **可见性**：启动区的“已加载项目指令”在文件名后列出它展开的引用，例如 `AGENTS.md（引用 docs/style.md、docs/testing.md）`。系统提示中只放展开后的正文，不额外包裹标签；层级文件仍用 `<project-instructions path>` 包裹 |
| N11 | **冻结**：展开在加载时完成一次，会话中途被引用文件变化也不重新加载，与层级文件一样在启动、`/clear` 和恢复会话（9b）时重新加载 |

## 设计

| 模块 | 改动 |
| --- | --- |
| `prompts.py` | `instruction_candidates()` 末尾追加 `<root>/.mosscode/AGENTS.md`，并为每个候选文件确定允许范围（N7）。新增 `expand_includes(path, text, boundary, visited, stack, depth) -> (text, includes, problems)`，处理 N1–N9。`InstructionFile` 增加 `includes: tuple[Path, ...]`。`instructions_section()` 的说明加入 I2 的补充句 |
| `security.py` | 复用 `inside()`；不改动 |
| `conversation.py` | `_load_context()` 的提示带上引用列表（N10） |
| `docs/reference/prompts.md` | “项目指令”一节写明层级、@include 语法和限制 |

展开逻辑使用纯函数，输入路径和文本，返回展开结果和问题列表，不依赖全局状态，便于单元测试。

```
expand(file, depth, stack):
    for line in file 的各行:
        在代码块中，或不是 @ 引用行 → 原样保留
        target = resolve(相对 file 所在目录的路径)
        不在 boundary 内        → 越界说明 + 提示
        target in stack         → 环路说明 + 提示
        target in visited       → “已在前文加载”
        depth + 1 > 5           → 深度说明 + 提示
        读取失败                → 无法读取说明 + 提示
        否则 visited.add(target)；替换为 expand(target, depth + 1, stack + [target])
```

## 取舍

| 决定 | 理由 |
| --- | --- |
| 由通用到具体排列，不按“高优先级排前面”（用户初稿） | 模型对靠后的内容更敏感；真正决定优先级的是明确的冲突规则。现有实现和 Claude Code 都按这个方向排列，改动最小 |
| 保留父目录的 AGENTS.md，不改为固定三层 | 支持 monorepo：上级目录放公共规范，子项目放各自的规范。用户初稿的三层（项目根、`.mosscode/`、用户目录）都包含在内 |
| 只解析独立一行的 `@路径` | 行内解析会把装饰器、邮箱和 Markdown 中提到的 `@` 误当成引用 |
| 环路用祖先栈，重复用 visited 集合 | 只用一个 visited 集合时，“两个文件引用同一份规范”会被误报为环路 |
| 每个层级文件的允许范围不同 | 用户级文件引用用户目录中的公共规范是合理需求；项目文件引用项目外的文件会把不受控的内容带进系统提示 |
| 引用失败时保留一行说明，不中止加载 | 一个写错的路径不应让整份项目指令失效；用户在启动区能看到原因 |

## 不做

`AGENTS.local.md` 等个人覆盖文件、按子目录按需加载（进入子目录时才加载其中的 AGENTS.md）、会话中途热加载、引用网络地址。
