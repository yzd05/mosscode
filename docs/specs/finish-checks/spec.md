# 完成前的确定性验收

日期：2026-11-13。状态：已实现。

## 范围

复用现有 Hook 信任、命令执行、日志和 Agent Loop。增加默认关闭的同步 `pre_finish` 命令 Hook；不新增任务系统、依赖或模型评估器，不改 `turn_end` 的语义。

## 行为

- 主对话执行可能改变状态的工具后，在模型准备正常结束时执行检查。纯问答、只读工具、网页查询、笔记操作及现有命令分类器确认的只读命令不触发；无法确认只读的命令保守触发。计划模式不执行检查。
- Hook 只能使用同步 command 动作，不能 `once`，沿用既有配置来源和项目信任。未配置时行为不变。条件可使用 `iteration` 和 `attempt`，检查命令由用户配置，不由模型生成。
- 所有命中的检查退出码均为 0 才放行。非零、超时、启动失败都阻止本次完成，记录实际结果，并给模型失败反馈以继续修复。每轮最多失败 3 次；达到上限以 `finish_check_failed` 提前结束，不发出成功完成信号。共享调用预算和最大迭代数仍有效。
- 检查在同一次 Agent Loop 内续跑，失败草稿保留在历史中，但不作为最终 Completed 事件交付。已流出的文字可能可见，须同时展示检查状态；用户取消时终止检查进程，不再发出模型请求。
- 有后台任务时暂缓检查，沿用既有通知续跑机制；待验收标记跨通知轮次保留。已失败或取消的待验收任务在用户继续后重试；`/clear` 清除标记。标记不持久化到跨进程恢复的会话。
- 只在主对话执行，不自动给子 Agent、Skill fork 或其他进程安装相同检查。团队成员完成状态由现有团队工具管理，不以本检查作为团队全局完成证明。
- 检查输出有既有脱敏、截断、超时和日志边界；通过仅证明配置命令通过，不代表任务完全正确。

## 验收

使用现有模拟 Provider 和临时项目验证：失败反馈后实际修复并通过、连续失败上限、无配置及只读任务不触发、非零/超时/缺少命令、取消、后台通知续跑，以及不可信项目 Hook 和不支持配置仍不能执行。只运行相关测试、文档检查和 Ruff。

## 验证结果

- 新增 19 个参数化后的用例，复用既有 Hook、Provider、命令和等待夹具；覆盖实际失败后写入修复、三次失败停止、只读跳过、信任、取消、后台续跑、预算和无界面输出。
- Hook、Agent、CLI、目标、回复恢复和调用预算相关测试：155 项通过。最后的直接相关检查中，Agent 和 CLI 31 项通过，完成前验收和文档 45 项通过。
- Ruff check、format check（257 个文件）和补丁空白检查通过。
- 未运行全量测试，不把受控测试当作真实模型任务成功率的证明。
