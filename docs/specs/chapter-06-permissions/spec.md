# 第六章：工具权限与交互确认

> 后续更新：2026-10-15 按用户新表格实施四档权限，plan 的写入/命令改为可审批。当前行为以 [四档权限规格](../permission-modes/spec.md) 为准，以下保留本章原始验收记录。

日期：2026-10-12。状态：用户已确认范围与优先级，已实现并通过本地验收，证据见 [validation.md](validation.md)。本章沿用 code-spec；专用文件工具做项目路径隔离，命令默认需确认，不引入系统级或容器沙箱。

## 已确定的范围

- 六个已有工具统一经过执行前权限检查。已知危险命令通过内置正则硬拦截，配置和用户确认均不能放开。
- 专用文件工具读、写、编辑、查找、搜索只能访问项目根目录内的目标；命令工具的工作目录也受路径检查。
- 解析符号链接及 Windows 支持的目录链接后，按路径组成部分判断包含关系，不能用字符串前缀判断。新文件检查解析后的父目录；搜索遍历也要检查实际目标，不能仅检查搜索入口。
- 这属于应用层限制。现有命令工具启动的 PowerShell、Python 等子进程仍拥有操作系统给予的权限；工作目录、正则和确认不能保证命令的实际文件访问范围。Windows Job Object 现有用途是管理进程生命周期。
- 规则结果只有 allow、deny；未命中规则时是否询问用户由权限模式决定。
- 用户可本次、本会话、永久放行。普通拒绝作为结构化工具结果回写，Agent Loop 可调整策略；沿用原有迭代上限与取消行为。
- 本章不做网络限制、资源配额、审计日志、上下文压缩。

## 已确认的权限行为

1. 严格模式所有可授权操作需确认；默认模式未命中规则时只读工具放行、写入和命令确认；放行模式跳过未命中规则的确认。所有模式均保留硬限制、计划模式限制和最终生效的显式 deny，用户已明确放行档位也必须遵守拒绝。严格模式的会话/永久规则仍保存，但不免除逐次确认。
2. 会话临时 > 本地级 > 项目级 > 用户级；同一层 deny 优先；高层可覆盖低层。永久放行写本项目本地级文件，绑定具体工具与文件；命令绑定精确命令和工作目录，不自动扩大为 glob 授权。

## 实现设计

### 执行边界

工具注册中心仍为调用入口。未知工具、参数格式与 Schema 错误继续沿用已有错误；合法参数进入权限策略后，只有获准的调用才能创建实际执行任务。

路径与危险命令属于硬限制，先于可配置规则；计划模式继续在执行入口限制副作用工具。用户等待确认的时间不算工具执行超时。获准后执行前重新检查路径，降低等待期间链接变化造成的风险；本章不声称防住其他进程并发更换链接的所有竞争情况。

权限文件本身不应允许模型通过写文件、编辑文件自行修改。永久授权由用户确认后交由权限模块写入；应用层无法约束任意 shell 程序重写配置的事实也需如实说明。

### 配置和匹配

文件位置：

- 用户级：`~/.mosscode/permissions.yaml`。
- 项目级：`<root>/.mosscode/permissions.yaml`，可作为项目共享设置。
- 本地级：`<root>/.mosscode/permissions.local.yaml`，作为本机本项目设置。
- 会话级：只存在当前进程内存，退出失效。

规则文件独立于 Provider 配置，不读取真实 API 密钥。配置解析出错应给出文件和字段错误并停止启动，不能静默转为放行。

规则语法：

```yaml
allow:
  - Read(src/**)
  - Bash(git status)
deny:
  - Write(.git/**)
```

映射 `Read`、`Write`、`Edit`、`Glob`、`Grep`、`Bash` 到已有工具名，并可接受真实工具名。`Bash` 是配置兼容别名，Windows 上仍执行现有 PowerShell 工具；UI 显示真实命令和工作目录。

没有通配符时完整精确匹配；有通配符时进行明确的 glob 匹配。文件规则使用归一化的项目相对路径，定义 `*` 与 `**` 的跨目录行为，并测试 Windows 分隔符和大小写。

命令规则匹配整个命令，不按字符串前缀授权。`Bash(git *)` 不应因为前半段符合而顺带允许追加的其他命令；含串联、管道、重定向、命令替换等复杂 shell 结构的操作不能仅靠简单 glob 获得放行。内置黑名单检查完整原始命令，不承诺识别所有混淆和间接执行。

会话与永久授权限定实际操作范围；自动生成规则采用 `{rule: Tool(pattern), exact: true, cwd: <目录>}` 对象，cwd 仅用于命令，文件名中的通配符字符不会被扩大解释。新增规则未成功持久化时返回 permission_save_failed，不执行调用。保存采用原子替换，保留其他已有规则；保存时重新读文件，同层出现新的 deny 仍拒绝执行。配置 mode 按加载层覆盖，CLI 显式档位优先，界面切换只在当前会话有效。

### Agent 与界面

PermissionPolicy 管理硬检查、规则与审批队列；ToolRegistry 校验参数后先授权，再创建执行任务。ApprovalRequest 是独立事件，execute_batch 同时等待执行任务和审批队列，TUI 通过请求 ID 提交选择；权限策略不导入 TUI。请求包含调用 ID、工具名、实际目标或命令、工作目录、请求原因和内容预览；审批请求不进入模型对话历史。

审批面板在现有输入区域下方显示，中文说明，键盘选择本次允许、会话允许、永久允许、拒绝；蓝色高亮当前选项，背景和字体沿用终端。多个待审批调用排队显示，避免并行读工具造成多个面板争抢输入。

Esc 拒绝某个操作并继续循环；Ctrl+C 取消整个任务。退出、取消时清理待审批请求和任务，不执行悬空调用，并保持工具调用和结果配对。审批选项复用 KeyboardOptions，点击不执行，蓝色高亮且不铺背景。

无界面的 `--prompt` 不挂起等待交互；未获策略放行的需确认操作返回 `approval_required`，由模型调整或结束。自动模式/计划模式与权限信任档位是两个维度，不把放行模式命名为自动模式。`/permissions` 带三个参数的中文命令补全，状态行分别显示任务模式和权限档位。

## 验收计划

1. 内置危险命令在所有档位、显式 allow 和永久授权下仍拒绝；合法相似命令不因宽泛匹配误拒绝。
2. 项目内正常路径、项目外绝对路径、`..`、同前缀相邻目录、新建文件、符号链接、Windows 目录链接，以及搜索入口和搜索目标分别验证。链接测试需记录平台是否实际支持。
3. 精确、glob、别名、不同配置层冲突、同层冲突、错误配置、复杂命令不能借前缀规则放行，行为与最终确认的优先级一致。
4. 本次授权不影响下一次；会话授权匹配限定范围且退出失效；永久授权重启后有效，并写入最终确认的层级。持久化失败有明确反馈。
5. 审批期间工具无副作用，等待时间不计执行超时；并行工具的审批顺序、拒绝后调整策略、计划模式不可提升、无界面不等待、取消/退出清理与历史配对均验证。
6. 权限配置不能被专用写入工具自行修改。伪造的工具输出、模型参数和文件内容不能直接产生用户授权。
7. UI 用假模型和临时项目验收；完整回归、编译和 Windows 控制台烟测；不使用真实 API 和真实凭据。

最终验收证据记录在 validation.md。真实服务的模型策略效果与操作系统级隔离不作为本地假模型测试的结论。
