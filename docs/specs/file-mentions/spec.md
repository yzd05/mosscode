# `@` 文件引用

日期：2026-11-03。状态：已实现，已验收（2026-11-04，M137–M141）。

来源：
- [产品差距评审](../../research/product-gap-review.md)的 B1 和 R7，属于“完善十：上手与安全网”。`/rewind` 完成后接着做这一项（2026-11-03）。
- Claude Code 的做法：输入 `@` 后弹出文件和目录候选，模糊匹配；发送时由程序读取被引用的文件，像模型调用过 Read 一样附在消息后面，目录给出列表；支持 `@文件#L10-20` 只引用几行。

## 问题

要让模型看某个文件，只能写出路径，再等模型调用 `read_file`。这多花一次请求，路径也容易打错。

## 已确认的事实

| # | 位置 | 内容 |
| --- | --- | --- |
| F1 | `tui.py` | 输入框的提示菜单（`#command-hints`）由 `_refresh_hints` 按整个输入框的内容生成，`Hint.value` 是选中后写回输入框的完整文本；↑ / ↓、Tab、Enter 的处理已经存在 |
| F2 | `tools/files.py` | `read_file` 输出“行号 + Tab + 原文”，单页最多 2000 行、56 KiB，截断时提示下一页的 offset；读到图片时附上图片。读取后 `FileState` 记为已读，之后可以直接编辑 |
| F3 | `permissions.py` | `operation()` 做硬性检查（例如凭据文件），`decide()` 处理显式拒绝规则；项目外的路径默认“需要确认” |
| F4 | `tools/search.py`、`search_worker.py` | 有 `rg` 时用 `rg --files`，否则用内置遍历；两者都遵守 `.gitignore`，跳过 `.git`、`.venv`、`node_modules` 等目录 |
| F5 | `agent.py` | 用户消息在第一次回复成功后才进入历史；`synthetic` 不为 None 的消息不是用户输入的，没有 id，不是回退点 |
| F6 | 依赖 | Textual 自带 `textual.fuzzy.Matcher`，2 万个候选的匹配约 30 ms |

## 需求

### 补全（AC）

| # | 要求 | 验收 |
| --- | --- | --- |
| AC1 | 光标前的词以 `@` 开头（`@` 在行首或空白之后）时，提示菜单列出项目中的文件和目录，按模糊匹配排序，最多 12 项。文件列表遵守 `.gitignore`，有 `rg` 时用 `rg --files`，否则用内置遍历 | 输入 `@tui` 列出 `src/mosscode/tui.py`；`.gitignore` 忽略的文件不出现 |
| AC2 | 选中文件后，把这个词换成 `@路径` 加一个空格，光标停在它后面；选中目录时换成 `@目录/`，菜单继续列出目录中的内容。路径含空格时加引号：`@"a b.txt"` | 在消息中间补全后，光标后面的文字不变 |
| AC3 | 邮箱等 `@` 前面不是空白的文字不触发；Esc 收起菜单后，同一段文字不再弹出 | 输入 `a@b` 没有菜单 |

### 发送（AT）

| # | 要求 | 验收 |
| --- | --- | --- |
| AT1 | 发送消息时，每个指向存在的文件或目录的 `@路径` 都会被读取。路径相对项目根目录，也可以是绝对路径或 `~` 开头；末尾的标点不算路径。`@文件#L10-20` 只读这几行，`#L10` 从第 10 行开始读 | `看下 @a.py。` 附上 a.py；`@a.py#L2-3` 只附第 2、3 行 |
| AT2 | 文件内容和 `read_file` 的结果一样（行号、截断提示、图片），并记为已读，模型可以直接编辑。目录给出一层列表，最多 100 项 | 引用后模型直接 `edit_file` 不报“需要先读取” |
| AT3 | 一条消息最多附上 10 个引用。附上的内容总量超过 112 KiB 后，后面的文件只给出路径，提示模型自己读取 | 引用 3 个大文件，第 3 个只有路径 |
| AT4 | 读取不经审批，因为路径是用户自己输入的；但硬性检查和显式拒绝规则照样生效，被拒绝的文件只给出原因 | `deny: read_file(secret.txt)` 时不附上内容，提示原因 |
| AT5 | 用户消息保持原样（显示、回退、记忆提取、标题都用原文）；附上的内容是紧跟在后面的一条程序生成的消息，写入存档，恢复会话后仍在上下文中。回退到这条用户消息之前时，附件一起去掉 | 存档中用户消息后是一条 `synthetic` 为 `file-mentions` 的消息 |
| AT6 | 界面在用户消息下面显示附上了什么，例如“└ 已附上 src/a.py（120 行）”；恢复会话时也显示。`-p` 同样展开引用 | 无界面模式中引用的文件进入请求 |

## 设计

- **`mentions.py`（新）**：
  - `find_mentions(text, root)` 找出 `@` 引用并解析成存在的路径，去掉末尾标点和 `#L` 行号范围。
  - `attach(mentions, registry)` 逐个读取并生成附件消息。文件交给注册表中的 `read_file` 执行，所以格式、图片、已读记录都和工具一致；权限只做 `operation()` 和 `decide()` 的拒绝判断。
  - 补全用的 `FileIndex`：在线程中列出项目文件，缓存 10 秒；`candidates(query)` 加入各级目录，用 `Matcher` 排序，分数相同时短路径在前。
- **`agent.run(..., attachments=)`**：附件消息和用户消息一起发送，第一次回复成功后一起进入历史。
- **`Conversation._reply`**：用户输入的消息（非 fork、非程序生成）在调用 `agent.run` 前展开引用，并发出 `FilesAttached` 事件。
- **界面**：`_refresh_hints` 在没有命令提示时检查光标前的 `@` 词；`action_complete_hint` 写回文本后把光标放到补全内容之后。`resumed_rows` 把附件消息显示成一行说明。

## 不做

- 运行中排队的消息不展开 `@`：排队消息在两次请求之间合并，展开需要在那里读取文件，先不做。
- MCP 资源（Claude Code 的 `@server:resource`）不做。
