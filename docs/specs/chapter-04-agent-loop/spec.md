# 第四章：Agent Loop

> 后续更新：计划模式当前按 [四档权限规格](../permission-modes/spec.md) 执行，写入/命令可申请审批；下面保留第四章最初的只读计划模式设计记录。

日期：2026-10-10。状态：已实现，本地验收通过。用户授权开发本章，沿用 code-spec；参考章节用于澄清行为，不继承计划落盘、权限或交互确认等额外功能。证据见 [validation.md](validation.md)，真实 API 与 POSIX 主机尚未联调。

## 目标与已确定边界

替换第三章“一批工具 + 一次禁用工具续答”的限制。每次输入由同一 Agent 运行时持续请求模型、执行工具、回写结果，直到完整响应不再请求工具，或达到明确停止条件。三种 API 适配、已有工具超时、取消清理、原生背景、流式 thinking/正文、最终 Markdown 和内存历史继续使用。

- 自然完成：完整 assistant 响应没有工具调用。ReAct 不要求模型一定提供可见 thinking，不能伪造思考过程。
- 迭代上限：默认 25 次模型请求；最后一轮的合法工具调用仍执行并补齐结果，随后提示已达上限，不再额外请求模型。上限按模型请求数计，不按工具个数。
- 连续未知工具：连续 3 轮全部调用注册中心不存在的工具时停止。含已注册工具的轮次重置计数；普通工具错误不冒充未知工具。
- 取消：停止当前请求、清理运行中的工具、不再启动后续批次；保留实际执行结果并补齐未执行/取消结果，可继续下一次输入。
- 流错误：停止，不自动重试。未完整接收的调用不执行；已完成的历史不丢失。
- 本章不加权限确认、上下文压缩、持久化、计划文件、计划审批工具或其他 Agent 框架。

## 运行时与事件

新增独立 `agent.py`，不依赖 Textual、Rich 或具体 SDK，拥有运行状态、规范历史、计划模式、Token 累计和循环。`Conversation` 保留现有调用接口，委托运行时，避免 TUI 与无界面入口各有一套循环。

每次模型请求由流式收集器沿同一流实现两路处理：实时转发正文/thinking/调用状态，保存完整 Completed 快照用于调用判断和历史提交。Provider 仍拼接协议特定工具参数，不把工具执行搬进 SDK 自动 runner。

事件包括：文本/thinking Delta、ToolProgress、完整响应边界、每轮 IterationProgress、UsageUpdate、最终 Completed、RunStopped。RunStopped 明确自然完成、上限、未知工具、取消和错误原因，并携带最近一批工具的收尾结果；取消/错误事件后仍按原接口抛出对应异常，便于现有调用方正确清理。消费者主动关闭生成器时只清理，不在 GeneratorExit 时强行发送事件。界面重复取消不会打断已开始的收尾。

用量按模型实际提供的输入/输出统计，每个完整响应只计一次，跨用户输入累计。缺失不是零；部分缺失显示已知下限，全缺失显示未提供。Chat 兼容端点沿用已有 stream_usage 配置，不强行注入可能不兼容的选项。进度显示轮数，完成保留本次总耗时。

## 工具调度

Tool 新增默认 false 的 read_only 元信息。read_file、glob、grep 为只读且可并发；write_file、edit_file、execute_command 保守串行，即使某条 shell 命令看起来只是读取。未知工具也按串行边界处理。

按模型顺序扫描调用，连续只读合并，最多 4 个同时执行；遇到副作用调用先等待前面的只读批次，再单独执行该调用。不会跨写操作重排读取。并发完成事件可及时输出，工具行位置按原始顺序，历史结果始终按原始顺序回灌。

调度层负责取消并等待全部本轮任务收尾；利用现有 ExecutionCancelled 保留已开始文件 I/O 的真实结果，不能通过 gather 丢失取消异常携带的结果。任何退出路径都为本次完整 assistant 中的每个调用配齐结果。

## Plan Mode

- 默认普通模式，提供六个工具。
- `/plan` 仅切换模式并提示后续问题将规划；`/plan 任务` 同时切换并开始处理任务。模式跨输入保持。
- 计划模式只注入 read_file/glob/grep，并追加只读计划提示；执行入口再次检查 read_only，兼容服务违规请求写/命令时返回 plan_blocked，绝不执行。
- `/do` 切回普通模式，用内置提示请求执行上文计划；`/do 任务` 允许明确补充执行目标。空会话的 `/do` 只切换并提示先提供任务，不让模型凭空开工。
- 不建立完整可扩展命令框架。补全列表、中文说明、/help 和状态行增加上述模式提示。忙碌时拒绝切换。

## 历史与显示

每轮完整 assistant 请求与结果依次提交；自然完成的最终响应提交后结束。第一轮未完成时仍回退用户输入；后续轮未完成时保留已有 user/assistant/tool 历史，不保存部分 assistant。合法模型调用中的无效 JSON 仍返回结构化结果供下一轮调整。

每轮前置文字、工具行、摘要和最终答复留在同一历史区。并发完成不改变工具行位置。运行时的通知不是虚构模型答复；上限/未知工具提示作为本地运行结果展示。保留滚轮、快捷键、输入焦点、单色 Logo 和文字亮度。

底栏固定显示当前“自动模式”或“计划模式”，运行阶段、轮次、耗时与用量作为附加信息，结束后不显示“就绪”。普通文字沿用终端前景；工具成功使用浅绿，参数和 Markdown 行内代码使用蓝色，写入/编辑/命令与未执行状态使用琥珀色，失败使用红色。仅设置前景，不增加背景填充；模式显示不改变运行时权限或工具范围。

只包含工具、不包含文字的后续响应也建立独立条目，不覆盖上一轮内容；空条目在界面隐藏。窄窗口省略重复历史按键提示，仍能滚轮和快捷键查看历史。

## 任务与验收

1. 提取独立 Agent、双路收集器、事件与停止条件。测试多轮依赖任务、自然完成、上限、未知计数重置、断流、取消和继续输入。
2. 加入只读元信息与保序并发调度。用可控工具和屏障证明只读实际同时执行、写操作前后隔离、最多 4 个并发、完成事件及时、结果原顺序、取消无遗漏/残留任务。
3. 接入计划模式。请求体证明只发送只读定义；强制返回写入/命令调用证明执行入口拒绝；验证 /plan、/do 自动触发与模式保持。
4. 接入轮次、用量、停止事件到 TUI/CLI。验证中间响应实时显示、最终 Markdown、并发工具行顺序、中文补全、未知用量不显示伪造零、错误后仍可输入。
5. 用实际 SDK + 模拟 SSE 验证三种协议连续多轮工具回放，保留签名/必要 reasoning；重跑相关原有回归，将第三章限制测试调整为本章循环契约。
6. 更新 README 和验收记录，查看实际 Textual 预览并运行 Windows 控制台烟测。真实 API 与 POSIX 主机未运行时明确标记未验证。
