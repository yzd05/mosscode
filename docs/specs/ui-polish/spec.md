## 现状与差距

对照对象是 Claude Code、Codex CLI、OpenCode、Gemini CLI。它们在布局上各不相同，但有几点是一致的，MossCode 目前都没有做到。

| # | 方面 | 成熟产品的共同做法 | MossCode 现在 |
| --- | --- | --- | --- |
| G1 | 品牌 | 有一个抽象、好认的标志和一个品牌色，logo、输入提示符、转圈动画都用它（Claude Code 的橙色、Gemini 的渐变色字标、OpenCode 的双色字标） | 白色小幽灵是通用的像素吉祥物，没有辨识度；全界面没有品牌色；吉祥物高 5 行，比右侧 3 行信息高出一截 |
| G2 | 启动区 | 版本号、目录是弱化的；目录缩写为 `~`，多数显示当前分支；有一行新手提示 | 三行同样亮度；目录是完整的绝对路径；没有提示 |
| G3 | 文字层级 | 正文最亮；耗时、结果摘要、按键提示、占位文字用一档灰色，一眼能分开“回答”和“过程” | 所有文字同一亮度。工具结果摘要、耗时、“✻ 完成”与回复正文一样抢眼；输入框的占位文字看起来像已经输入的内容 |
| G4 | 运行状态 | 输入框上方有一行带动画的状态（转圈符号 + 阶段 + 用时 + 取消提示） | 阶段写在底部状态栏中间，没有动画，和权限档位、上下文占用挤在一行里 |
| G5 | 状态栏 | 左边是档位和提示，右边是上下文占用等数字，都是弱化的 | 所有项用“ · ”连成一行，同一亮度 |
| G6 | 输入框 | 提示符有颜色；边框颜色随模式变化（计划、接受编辑一眼可见） | `❯` 与正文同色，上下横线不随模式变化 |
| G7 | 选择列表 | 选中行前面有 `❯` 指示，说明文字弱化 | 只靠蓝色加粗区分选中行；审批面板每个选项的名称和解释连成一句，同一亮度 |
| G8 | Markdown | 标题左对齐；代码块有语法高亮 | 写入滚动历史时一级标题被居中到整行中间，分隔线是一排 `-`，表格前后各空两行；代码块是纯文本 |
| G9 | 字形 | — | `⏸ 计划模式` 的 `⏸` 在 Windows Terminal 中被当成 emoji，画成蓝色方块并压住后面的“计”字（预览时实拍到） |

布局本身（内联显示、完成内容进终端滚动历史、上下横线的输入区、`❯` / `●` 的消息排版、工具行 `Read(path)` + `└` 摘要）与 Claude Code 一致，不是差距所在，这次不动。

## 改动

颜色：新增三个常量，其余不变。

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 品牌色 | `#b48cff`（紫色；黑底上对比度 7.6:1） | 输入框的 `❯`、转圈符号、代码中的关键字 |
| 次要文字 | `#8b929c`（黑底上对比度约 6:1，高于 WCAG AA 的 4.5:1） | 见 R2 |
| 横线 | `#5c636e` | 输入框和选择面板的横线、Markdown 分隔线 |

品牌色选紫色，是因为绿、蓝、琥珀、红在界面里都已经有含义（成功、参数、进行中、失败），紫色是唯一不会被误读成状态的颜色。logo 自己的颜色（彗星的灰蓝 → 蓝 → 近白）只在 logo 中出现；彗星的蓝与参数的蓝太接近，所以没有拿它当品牌色。想让 `❯` 和转圈符号跟 logo 同色，只需改 `appearance.py` 中的 `BRAND_COLOR` 一个常量。

画法：用八分之一高度的方块字符（`▁▂▃▄▅▆▇█`），图形的上边缘可以按 1/8 行移动，所以能画出平滑的弧线。对照的四个产品用的都是半格像素或字符字标，没有这样画的。彗星的每一列都从底部向上填充，不需要反显或一格两色。已在 Windows Terminal 中确认，写入滚动历史和显示在实时区域（Textual 内联渲染）两种情况下结果相同。

右侧信息：版本号和目录用次要文字；目录中的用户主目录缩写为 `~`；在 Git 仓库中目录后面显示当前分支（直接读 `.git/HEAD`，不启动 git 进程；游离 HEAD 时显示提交号的前 7 位）；增加一行提示。logo 旁边排名称和模型两行，目录和提示空一行排在下面。

### R2 次要文字

下列内容改用次要文字的灰色，其余文字保持终端正常前景色：

- 启动区的版本号、目录与分支、提示行；
- 工具行的耗时、`└` 连接符、成功时的结果摘要；diff 的行号；
- “✻ 完成 · 12.3s”、“思考用时 1.2s”；
- 输入框的占位文字、各面板底部的按键提示、命令候选中未选中行的说明；
- 状态栏中除档位徽标以外的项（已有颜色的项保持原色）；
- 用户消息下方的图片、附件说明，清单面板的标题。

不变灰的：回复正文、用户消息、代码、diff 的内容、失败工具的错误详情、审批面板里的操作预览。现有少数几处用 `dim` 的地方（清单面板、图片说明、审批预览的 diff 头）统一改成这个灰色，界面不再输出 dim 指令。

现在：

```
✓ Read(src/app.py) · 0.0s
  └ 已读取 42 行

✻ 完成 · 12.3s
```

改后（方括号里的是灰色，实际没有方括号）：

```
✓ Read(src/app.py) [0.0s]
  [└ 已读取 42 行]

[✻ 完成 · 12.3s]
```

工具名、参数的颜色和 `✓ / × / ! / ●` 标记不变。

### R3 运行状态行

运行中，输入框上方显示一行状态：转圈符号（品牌色，每 0.2 秒一帧，`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`）、阶段（琥珀色）、其余（灰色）。空闲时这一行不占位置。

现在（在状态栏里）：

```
默认权限 · 执行工具中 · 2/25 轮 · 1.3s · Esc 取消 · 上下文 约 9K / 1M（1%）
```

改后：

```
⠹ 执行工具中 · 2/25 轮 · 1.3s · Esc 取消
────────────────────────────────────────────────────────────

────────────────────────────────────────────────────────────
```

### R4 状态栏

- 档位徽标在左，“上下文 …”和“缓存命中 …”靠右对齐；其余项（沙箱、思考强度、目标、排队、后台任务、团队）仍跟在档位后面。一行放不下时退回现在的顺序排列并折行。
- 除有颜色的徽标和警示项外用次要文字。
- `⏸ 计划模式` 改为 `‖ 计划模式`（已在 Windows Terminal 中确认 `‖` 占一格、不被当成 emoji）；`⏵⏵` 显示正常，不变。

### R5 输入框

- 占位文字用次要文字；`❯` 用品牌色加粗（`!` 命令模式仍是琥珀色的 `!`）。
- 上下横线默认是灰色（`#5c636e`），随权限档位变色：计划模式琥珀色、接受编辑绿色、跳过审批红色。颜色与状态栏徽标一致，徽标文字仍在，不只靠颜色。

- 命令候选右侧的说明、审批选项的解释用次要文字；选项名称用正常前景色。

### R7 Markdown

实时界面和写入滚动历史的内容保持一致：

- 一级标题左对齐、加粗加下划线；二级及以下加粗。
- 分隔线画成一条灰色的 `─`。
- 表格、列表前后各只空一行。
- 代码块按语言做语法高亮：标了语言的代码块用固定的几种前景色（关键字、字符串、注释、数字），不铺底色；没标语言的保持纯文本。

### R8 间距

- “思考用时”一行改为灰色的 `✻ 思考 1.2s`，与下面的回复之间空一行。
- 回复以代码块或表格结尾时，“✻ 完成”前面只空一行（现在实时界面里会空两行）。

## 不做的事

- 不改布局和交互：内联显示、终端滚动历史、按键、命令、面板的位置都不变。
- 不增加主题切换，不铺背景色，不改用户消息的灰色底条。
- 不改工具名、参数、选中项的颜色，不改 `● / ✓ / × / !` 标记。
- 状态栏不增加模型名（C7）。
- 浅色终端的强调色对比度没有适配，这是已记录的现状，这次不处理；新增的灰色在白底上对比度约 3:1，可读但偏淡。

## 实现记录

与方案的出入：

- **状态行不改变高度**（R3）。方案写的是“空闲时这一行不占位置”。实现时输入框上方原来就有一行空白，状态行就用这一行：空闲时它是空的，运行时显示阶段。这样任务开始和结束时界面高度不变，输入框不会上下跳。
- **代码高亮不新增颜色**（R7）。关键字用品牌紫、字符串用绿、数字用琥珀、注释用次要灰，`diff` 代码块的增删行用绿和红，都是界面里已有的颜色。
- **选中行的说明文字跟着变蓝**（R6）。未选中行的说明是灰色，选中行整行蓝色加粗，这样一行读起来是一个整体。
- **工具行的耗时前不再有“ · ”**（R2），与方案中的示意一致：`✓ Read(src/app.py) 0.0s`。
- **“✻ 思考 1.2s”与 `●` 对齐**（R8），不再缩进两格，实时界面与滚动历史一致。
- 成员窗格（`teams/pane_app.py`）里的审批列表没有加 `❯`，它是另一个独立的小界面，这次只把其中的 dim 换成了灰色。
- **滚动历史中分隔线后面只空一行**（R7）。Rich 在分隔线后面自带一个空行，后面跟表格或列表时会变成两行，实现时去掉了多出的一行。
- `/model` 列表中未选中行的协议与模型名保持正文颜色，没有改成灰色；方案只要求加 `❯`。

- 启动、运行中、对话、命令候选、`@` 文件候选、审批、提问、计划模式、`/model` 这九个场景与方案一致。

- 改变窗口宽度：界面运行时把窗口的宽度改小再改回（直接改窗口的尺寸，效果与拖动右边框相同）。缩窄后滚动历史按新宽度重排，状态栏改为顺排并折成两行；放宽后横线重新铺满，上下文占用回到右侧。
- `scripts/verify_inline_terminal.py` 在 Windows Terminal 中完整通过，包括它自己的“没有 dim 指令”检查。它起初在计划模式一步失败，与这次改动无关：`scripts/preview_agent.py` 写死的计划模式工具集合已经过时（现在多了 `todo_write`、`web_fetch`、`task_output`、`task_stop`），用改动前的源码运行同样失败。夹具改为只检查不变的部分：计划模式有读取工具和 `exit_plan_mode`、没有写入工具，执行阶段有写入工具。

## 后续改动

方案完成后又做了以下改动，上文中与之冲突的记录以这里为准；当前行为见 [界面](../../reference/interface.md)。

- **状态行空闲时不占位置**，回到方案 R3 的原意。上文“状态行不改变高度”的做法让启动区和“✻ 完成”到输入框之间各空三行；现在界面中各部分之间统一空一行，运行中状态行出现在输入框上方。
- **`/model`、`/resume`、`/rewind`、`/thinking` 列表的说明改为灰色**，成员窗格的审批列表加了 `❯`，长列表的滚动条改为一列灰色细条。上文“`/model` 列表……保持正文颜色”和“成员窗格……没有加 `❯`”两条不再成立。
- **审批和提问面板出现在输入框的位置**，上下两条琥珀色横线，输入框暂时隐藏；主界面和成员窗格相同。这改变了“不做的事”中“面板的位置都不变”一条。审批面板只占需要的行数，等待确认的工具行留在面板上方。
- **浅色终端有了自己的一套颜色**。启动时向终端查询背景色，浅色背景换用更深的强调色和灰色（对比度都不低于 4.5:1），`MOSSCODE_THEME` 可以指定。“不做的事”中关于浅色终端的一条不再成立；用户消息的灰色底条两套相同。
- 命令候选的按键提示与状态栏之间空一行，两者都是灰色，紧挨着时分不清。
